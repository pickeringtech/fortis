Agent mode: Closed decisions (LR B)

Appendix B: Closed decisions#

Human mode. Agent mode: Closed decisions, by topic. Source of truth: LR B.

Some questions come up whenever someone meets Fortis: why no semicolons, why give and not yield, why there is no ? operator. The LR keeps a table of these questions with their answers, the closed decisions (LR B). They are closed in the sense that Language 1.0 will not reopen them; each is stated normatively in the section cited beside it, and this appendix explains the reasoning, which comes back again and again to one principle: a piece of notation exists only if it changes what a reader may conclude about ownership, mutation, failure, effects or timing (LR 1.1).

Notation and syntax#

DecisionWhyLR
let and let mut declare; = only assignsA reader can tell a new name from a change to an existing one without looking anything up.LR 5.1
No semicolons: a ; is a parse errorNewlines end statements, with listed continuation tokens; a second way to end a statement would carry no decision.LR 3.2
.ft files, // the only comment form, documentation is the // run directly above a declarationOne comment form, so there is never a question of which kind documents what.LR 3.1, LR 3.7
Unsuffixed integer literals take their type from context (default Int) and must fit itAn out-of-range literal is a compile-time error, not a runtime surprise.LR 3.5
A float literal needs . or an exponent (f32 suffix for Float32); a Decimal literal ends in dThe literal's type is visible on the page: 10 is an integer, 10.0 a float, 10d a decimal.LR 3.5
A string literal is a StringView from static, converted to String (allocating) only where a String is expectedThe one implicit conversion in the language, and the checker counts its allocation.LR 3.5, LR 6.6
give ends a block that produces a value (yield was replaced)A distinct word for "this block's value", only where a block needs one; single-expression match arms need none.LR 5.4, LR 9.8
The type of fail is Neverfail can stand where any value is expected, such as a match arm.LR 5.4
catch e { … } names its failure explicitlyNo implicit binding enters scope.LR 10.4
Named arguments after positionals, in any order, each once; parameter names are public APIA call can say what each argument is, and a rename shows up as an API change.LR 5.8
Defaults are pure constant expressions, re-evaluated per call; no user variadics (pass a ListView[T])A default never hides an effect or shared state; List.of(…) is the one variadic form.LR 5.8, LR 6.2
Constructors are named create, of or from; there is no newConstruction is an ordinary associated function, named for what it does.LR 1.1, LR 9.2
No transparent type aliases: type is always nominalA reader never has to ask whether two type names are the same type.LR 6.9
No operator overloading (Money.add(a, b), not a + b)An operator always means the same thing; behaviour is named.LR 6.10
Range patterns, generic lambdas, const generics over N, associated types and explicit type arguments at calls are not in v1Each was left out of Language 1.0; the LR states the workaround (annotate the binding; take a generic parameter).LR 6.2, LR 6.10, LR 8.2, LR 9.5, LR 9.8
The standard package is fortis (fortis.prelude, fortis.text, …)One name for the standard library.LR 4.3

The decision about semicolons is checked like any rule. A stray ; is E-SYN-001 (LR 3.2), and the checker's record carries a correction that deletes it, as the syntax class allows:

Fortis
// reject: E-SYN-001
func main() {
  let a = 1;          // reject: E-SYN-001
}

Ownership and loans#

DecisionWhyLR
move p, copy p, editable p at the call site for existing places; fresh values need no markerThe call shows what happens to each argument.LR 7.5
move p.m() for owned self methods; p.m() for editable self methods and fn mut calls, on a place declared to changeThe transfer is shown at the call; that p changes is shown once, by its let mut or editable declaration, and the call takes the same exclusive loan editable p.m() would (older code writes it).LR 7.5, LR 7.6
return x of a local moves it, without moveNothing can use a returned local afterwards, so the marker says nothing the line does not.LR 7.5
alias p or editable p for an argument the result borrows fromA loan that outlives the statement is visible where it is taken.LR 7.6
Loans are lexical; no non-lexical lifetimesA loan ends at the end of its block, which a reader can see; to end one early, close a block.LR 7.3
No stored loans: no lifetime parameters on user types, E-OWN-053A reader never follows a region through a value's type; adding stored loans later breaks nothing.LR 7.7
Stored and returned loans both say from; within is removedOne word for "this loan comes from there".LR 7.6, LR 7.7
Two-phase borrows: reserve at argument evaluation, activate at call entryOrdinary calls such as sum = Money.add(sum, x) or fail are legal without special cases.LR 5.7
A loan from two origins is rejectedEvery returned loan has one origin a reader can name.LR 7.6
No partial movesA value is either owned or moved, never half of each.LR 7.2

Functions, closures and failures#

DecisionWhyLR
Non-Void functions end every path in return or fail; Void functions may fall off the endThere is no implicit last value to miss.LR 5.4
Closure kinds fn, fn mut, fn once are always writtenHow a closure may be called is part of its type and visible at its definition.LR 8.2
Lambdas take the same modifiers as functions; capture brackets only when non-emptyOne vocabulary for both; an empty fn[] would carry no information.LR 8.2
recovers is a modifier, written like tryA function that swallows a failure says so in its signature.LR 8.1, LR 10.4
or die is removed; use try mainA failing main prints one failure report and exits with status 1.LR 4.6
report is a statement; report e as receipt binds the receiptReporting consumes the failure, so it cannot also be propagated.LR 10.6
nostate is removed; teams that want to forbid let mut can turn on the opt-in lint no-local-mutation, which is not part of the languageWriting to storage that is fresh in the activation is not the mutate effect, so a nostate claim would add nothing a caller could rely on.LR 11.1, LR 11.2
pure, noalloc, async, try, recovers are the signature vocabulary; a full effects(…) clause was rejected as noiseTools show the inferred alloc, block and nondet; the signature keeps the claims a caller relies on.LR 11.2, LR B

or die is gone because try main already does what it did. When main fails, the runtime prints exactly one report of the failure to standard error and the process exits with status 1 (LR 4.6):

Fortis
// accept (exit status 1)
import fortis.host { Console }

export error Empty {
  code: "demo.empty"
  message: "nothing to do"
}

try func first(items: ListView[Int]) Int {
  if items.count() == 0 {
    fail Empty()
  }
  return items.get(0) ?? 0
}

try func main(console: Console) {
  let items: List[Int] = List.default()
  console.print("starting")
  let n = first(items) or fail
  console.print("first is ${n}")
}
output
starting

The second line never prints: first fails, or fail hands the failure to main's caller, and the report goes to standard error rather than standard output.

Contracts, aspects, interfaces and serialisation#

DecisionWhyLR
Contracts are applied by name in the modifier position (export FastCalculation func …), never with @, and take no argumentsA contract only subtracts, so it sits with the other claims.LR 11.5
@name(args) applies an aspect, and is the only use of @; aspects have needs, before, after, on failure, metadata; on failure may re-fail; specialisation with ...restAn aspect adds behaviour around a function and can never change a line inside it.LR 11.8
No around hook and no re-running the body; failure handlers run innermost firstA retry is a library function taking a fn once, not an aspect.LR 11.8
@observe(Schema) attaches an observation schema; it is a core aspectObservation uses the same mechanism as every other aspect.LR 11.8, LR 13
Interfaces are nominal; requires for sub-interfaces; bundles are satisfied automatically; no method bodiesHaving methods with the right names is not an implementation; default behaviour is a mixin.LR 9.5
derive Codec (= Encodable + Decodable); canonical toBytes/toText; formats are packages with …Serialised mixins; hand-written encode and derive cannot coexistOne description of a value's shape serves every format.LR 6.10
Projection by constructor spread ...copy p / ...move p; derive From[S]; to() on every typeNarrowing one type into another is written once, with its ownership visible.LR 6.10, LR 9.2
Constants include record and variant-map literals, declaration names and the Type.of(…) constructorsTables and route lists can be constants.LR 5.1
VariantMap[E, V] is written { Variant: value }; an optional callable is written (fn(…) R)?One entry per variant, checked for completeness; the parentheses say which part is optional.LR 6.9

The reading release (v0.0.2)#

v0.0.2 applies one principle: mark only what the reader cannot already see (LR 1.1). Every older form is still accepted, and fortis fmt rewrites each one that means the same; logging, @ignorable and derive Default are the author's choice, so they are left alone.

DecisionWhyLR
The entry main declares the capabilities it needs as parameters, supplied by type; export is implied on it, and args is declared only when usedAuthority stays explicit, with no ambient authority, but it sits in the signature, where a reader looks. Only the entry main receives capabilities.LR 4.6, LR 11.6
log.info, log.warn and log.error are statements that need no capabilityA log observes; it has no authority over the world, and its sinks are the platform's. console.print stays for the program's own output.LR 13, LR 11.6
A Void return type may be left out of a headA head with no result type returns nothing; writing Void adds nothing. A function type keeps its result.LR 8.1
In test and property bodies or fail is impliedA test can react to a failure it did not expect only by failing.LR 14
Checked arithmetic is written with operators under a handler: value * 10 + d or failOne handler covers the expression, and the arithmetic reads as arithmetic; an operator the checker proves stays a plain value.LR 6.4
An enum variant may be written bare where the expected type is known; a bare name that also names something in scope must be qualifiedThe expected type already says which enum; an ambiguous name is never guessed.LR 9.7
A | B => v in matchArms with the same result are one arm; the alternatives bind no names and take no guard.LR 9.8
A labelled argument puns: wanted for wanted: wantedThe name was written twice.LR 5.8, LR 9.2
Map[String, V].get takes a StringView keyA lookup allocates no key it then throws away.LR 6.7
@ignorable on a declaration, instead of discard at every callerThe author decides once that the result may be dropped.LR 5.5, LR 11.8
derive Default gives Name.default()A class whose fields all have defaults needs no hand-written constructor.LR 6.10, LR 9.2
The formatter does not print a lambda's inferred pure and noalloc; an expression-bodied lambda may leave out its result typeThe function type it is passed to already says both.LR 8.2

Numbers, collections and concurrency#

DecisionWhyLR
Float and Float32 have IEEE == but no Equatable, Hashable or ComparableNaN breaks those interfaces' laws.LR 6.5
Map and Set iterate in a deterministic order per build, so they may be used in pure codeIteration order never varies between runs or backends.LR 6.7
Length-refined collections are immutable; mutate an unrefined one and validate itA length refinement is a property of a value.LR 6.3
One cooperative thread per scope tree; the parallel and blocking pools need ShareableCooperative tasks can borrow; only data that may cross threads goes to a pool.LR 12.5
Blocking in async code is forbidden; launchBlocking takes a synchronous fn onceThe cooperative executor has one thread, so a blocked call would stall every task.LR 11.1, LR 12.5
Atomics are AtomicInt and AtomicBool, with seqcst and acquire/release onlyA small set of orderings a reader can reason about.LR 12.7
defer has only a block form, and defer await is not in v1A deferred block lowers to cleanup code at each exit and cannot suspend.LR 12.1
Entry point: main in the manifest's entry moduleThe program's start is named in one place.LR 4.6
Negative examples are marked // reject: E-XXX-NNNEvery example says what the checker must do with it.LR 0
Test rows are bound with cases { … } as row { … }The only name the table introduces is the one written after as.LR 14
