Agent mode: Fortis for agents

The Fortis guide#

Human mode. Agent mode: the Fortis reference for agents. Source of truth: the Language Reference.

This guide teaches Fortis Language 1.0, the core language, from the beginning. It is written for people: each chapter explains what a construct is for, shows it working, and shows what the checker says when it is misused. Its companion, the agent mode, states the same rules densely, by rule ID, with the records the tools print and the corrections that fix them, for AI agents writing Fortis.

Neither mode replaces the Language Reference ("the LR"), which is the source of truth. Every rule in this guide cites the LR section that states it, written LR 7.3; if the guide and the LR ever disagree, the LR wins and the guide has a defect (LR 0).

How the examples are checked#

Every example in this guide is a program that the real toolchain checks and runs, so the guide cannot drift from the language. An example's first line says what is expected of it, in the same notation as the LR (LR 0):

  • // accept: both checkers accept it, and it runs. A program with main runs on all three backends (the definitional interpreter, the development VM and native code) and prints exactly the output shown below it. // accept (exit status 1) marks a program that ends by failing, on purpose. A module without main has tests, and they pass on all three backends.
  • // reject: E-XXX-NNN (a real code, such as E-OWN-011, LR 7.3): the checkers reject it with exactly that code, on the line that carries the same marker, and report nothing else.
  • // illustrative: a shape with placeholders such as …, not a program.

The check is python3 -I conformance/tools/docset_check.py; where a backend still has a recorded defect for an example, the check names the defect, and the example stays as the language says it should behave.
