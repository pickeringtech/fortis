Known limitations of v0.0.2#

Human mode. Agent mode: Known limitations, by defect. The release note is v0.0.2.

v0.0.2 is a subset of the language (the ladder in the delivery plan). These are the open defects inside that subset that do not block the release: a valid program the checkers reject, a missing operation, two tools that disagree, or a checked program one backend refuses with a clear error and a non-zero exit while another runs it (X-343). A program the checkers accept and then run wrongly is listed only when v0.0.1 had the same defect: v0.0.2 is no worse, and those are in a section of their own (X-416). The last section lists what v0.0.2 leaves for later by design, as its release note says.

Valid programs the checkers reject, and library gaps#

DefectWhat you meetWorkaround
D-51.5An unused import is accepted with no warning.Delete the import. Nothing else changes.
D-52.1An error constructor is typed as its own kind, so a use that the language accepts where a failure is expected is rejected.Match the constructor's own type, or construct the failure where its own name is expected.
D-52.4Returning a call that passes a loan-holding closure is rejected even when the result is a plain integer.None recorded.
D-52.6A class you declare with the same name as a prelude type, such as Task, is checked as the prelude's linear type.Name the class something the prelude does not declare.
D-54.6For a parameter named with a keyword, fortisc vm reports a generic syntax error and fortisc check reports the keyword-specific one.Rename the parameter. Both tools refuse the program.
D-58.1Map has no iterate operation. A for loop over a map yields key and value tuples, which the language reference does not state.Write for over the map when a key and a value together are enough.
D-58.7Map has no remove and no contains.None recorded. Build a new map without the key, or scan it.
D-58.9Every text accessor can fail, so a comparator written as a pure function of two texts must recover.Recover inside the comparator, or do not mark it pure.
D-251A variant whose name is also a class's is rejected by both checkers, so the program does not reach the VM. List.of(Red) with the list's element type written out runs on the interpreter, the VM and native.Write the variant with its enum prefix, or do not declare a class of the same name. The list form already runs when the expected type is written.
D-252Both checkers reject an optional-chained method call such as lights.get(0)?.code(). The call does not reach the VM.Match the optional and call the method on the present value.
D-285A package whose manifest the loader refuses (conformance/packages/bad.policy) makes fortis check, run and test exit 2 with a message on standard error, and fortisc check exit 1 with a names record on project.yaml.Both tools refuse the package. Read fortisc's record; it names the manifest.
D-343A property runs 25 generated cases with fortis test and 100 with fortisc test, from different generators, so a property that fails on few inputs can pass on one and fail on the other.Run properties with fortisc test as well, and turn a failure it finds into an example test.
D-344The executor trace of a native build has no drop event for an owned optional local, for a temporary a ?? fallback made, or for the bindings of a match arm that owns its scrutinee; the interpreter and the VM trace each, and all three trace a fallback a ?? moved into its result. Cleanup runs once on all three, and the output and the log records agree.Compare traces on the interpreter and the VM; the native trace leaves those drops out.
D-363A tuple that holds a loan, such as (xs.get(0), 1), cannot yet be reassigned to a let mut binding that holds one, or returned from a function declared to return one: both checkers reject it as a loan where an owned value is required, although the Language Reference allows both. The same with an optional, t = xs.get(1), is accepted.Keep the loan in a binding of its own (let t = xs.get(0)) and the other values beside it, and reassign or return those separately.
D-365A defer that changes a list, such as defer { let v = xs.pop() }, is rejected while a binding of the same block holds a loan from that list inside an optional (let t = xs.get(0)), although a deferred block runs after its block's own loans have ended.Put the loan in an inner block that ends before the defer's block does, or make the change after the block.
D-400A function that binds a loan of a type whose cleanup does I/O (let t = alias b.t, or a ?? whose fallback fails) is charged that cleanup's effects, so a function that destroys nothing may be refused as not pure or asked to declare io.Declare the effect, or keep such loans out of functions declared pure.
D-401A let mut cursor cannot be reassigned (the checkers report a move of a lent owner), although a cursor is owned by its binding (LR 7.7).Make a new cursor in a binding of its own.
D-402After match move o of a binding that holds a loan (let o = xs.get(0)), the loan o held is not released, so the owner stays frozen for the rest of the block (xs.push is refused as a change under a live loan). New with this release's loan holders.Put the match and the binding in an inner block, so the loan ends with it.

One backend refuses the program#

DefectWhat you meetWorkaround
D-54.10A catch that returns inside a for is refused: fortisc test and fortis build exit 1, reporting that the typed IR uses a moved binding. The interpreter's test passes. A move in a returning branch, the other half of this entry, builds and its VM test passes.Run that test with fortis test. Keep the catch out of the loop, or bind the failure's value before the loop continues.
D-55.6A narrowed optional is not unwrapped in the native build. copy of a String? after != null, and a field read through a narrowed shared optional, each make fortis build exit 1 (rustc E0308, or no such field). The interpreter and the VM print the value.Run it with fortis run or fortisc vm.
D-55.8A dynamic fn in a list or a field does not build natively (rustc E0308 for the list, E0277 for the field). The interpreter and the VM run the programs.Run it with fortis run or fortisc vm.
D-55.16A local optional narrowed by != null and moved into a non-optional field is not unwrapped. fortis build exits 1 (rustc E0308). The interpreter and the VM print 7.Run it with fortis run or fortisc vm.
D-156A function-type parameter that owns its argument, fn(owned T), is lowered as a borrowed parameter. fortis build exits 1 (rustc E0631 when a named function is passed, E0308 when a lambda is). The interpreter and the VM run the call.Run it with fortis run or fortisc vm.
D-185A function whose result is an exclusive loan of its parameter, editable Cell from c, returning editable c (the Language Reference's own example in 7.6), does not build natively, nor does any returned exclusive loan: fortis build exits 1 (rustc E0308), because the returned loan is lowered as a read reference. The interpreter and the VM run it.Run it with fortis run or fortisc vm. Or change the value through the parameter inside the function and return nothing.
D-157.1A closure stored in a class field does not build natively (rustc E0277, the field's display). The interpreter and the VM run the program. Assigning a second lambda to one closure binding is a separate item and is rejected by both checkers.Run it with fortis run or fortisc vm. A dynamic fn is the heterogeneous form, and a field of that type is D-55.8, which also refuses natively.
D-244A type named like an item the generated Rust uses does not build natively: a class Vec, From or String, or a type alias String, in any program, Option beside an optional, and Box beside a recursive type (rustc E0107, E0404 and others). The interpreter and the VM run the program. Result, Rc, HashMap and the variant names Some, None, Ok and Err build.Rename the type, or run it with fortis run or fortisc vm.
D-245Arithmetic on literals at a sized integer type, such as let x: Int32 = -2147483647 - 1 or let y: Int32 = 2 + 3, does not build natively: the literals are emitted as 64-bit integers (rustc E0308). The interpreter and the VM print the value. A single literal builds.Write the folded literal (-2147483648, 5), or run it with fortis run or fortisc vm.
D-270A function declared to return one non-dynamic fn type may return two different lambdas. The interpreter and the VM run both (3 and 4). fortis build exits 1 (rustc E0308).Run it with fortis run or fortisc vm. Return one lambda, or declare the result dynamic fn when the two bodies really differ.
D-342A test's expect that compares an optional with a literal, such as expect first(names) == "a", does not build natively (rustc E0614). fortis test and fortisc test pass the test.Bind the present value first (let got = first(names) ?? "none", then expect got == "a"), or run the test with fortis test or fortisc test.
D-360A record literal that holds a loan, such as { item: xs.get(0), n: 1 }, does not build natively (rustc E0106), nor does a tuple with a loan passed to a read parameter of tuple type (E0308). The interpreter and the VM run them, and each cleanup runs once. A tuple holding a list's loan, such as (xs.get(0), 1), or an alias loan of a local, such as (alias own, make("p")), builds. A tuple bound first around a value of the function's own and returned as a from result (let t = (empty.get(0) ?? move d, 1), then return t from alias (Token, Int) from empty, which the Language Reference allows and the interpreter and the VM run correctly) does not build either (E0308), so a bearing aggregate from result has no spelling that builds natively yet.Run it with fortis run or fortisc vm. Or keep the loan in its own binding and pass it on its own.
D-361A binding that holds a loan on one path and a value of its own on another does not build natively (rustc E0308): an if that gives xs.get(0) on one branch and move d on the other, or assigning a new class value, which the binding then owns, to a let mut binding that held a loan. The interpreter and the VM run it, and the binding destroys only a value it owns.Run it with fortis run or fortisc vm. Or give the binding one kind of value: copy the loan, or keep the owned value in a binding of its own.
D-353A function whose result is an optional loan of text, such as (alias String from xs)? returning xs.get(0), does not build natively (rustc E0308). The interpreter and the VM run it. The same result of a class builds, except through a generic from function (D-387).Return an owned copy (let t = xs.get(0), then return copy t from a function returning String?), or run it with fortis run or fortisc vm.
D-387A generic function whose result is an optional loan of its type parameter, such as func first[T](xs: List[T]) (alias T from xs)? => xs.get(0), does not build natively when it is instantiated at a class (rustc E0277). The interpreter and the VM run it.Write the function for the class (func first(xs: List[Token]) (alias Token from xs)?), which builds, or run it with fortis run or fortisc vm.
D-390A byte string returned as the whole BytesView from xs result (=> b"abc"), or as a BytesView from static one, does not build natively (rustc E0515), nor does an if or match that gives a string literal on one branch and a view of a String through a loan on another (give "empty" beside give alias t.label, as StringView from t; rustc E0308), nor the outcome-expression spellings of that shape: or recover "missing" as a (alias StringView from xs)? result, or present("none") in an if branch of one (rustc E0308). The interpreter and the VM run them. A string literal as the whole StringView from xs result builds.Return the literal from a function of its own, or run it with fortis run or fortisc vm.
D-415An anonymous record returned by return r past a deferred block that reads it (let r = { n: 5, m: 8 }, defer { console.print("bye ${r.n}") }, return r) does not build natively (rustc E0382), whatever its field types: the record is moved by the return, where a trivial class, a tuple or an enum is copied. Both checkers accept it and the interpreter and the VM run it.Use a class or a tuple for the value, or run it with fortis run or fortisc vm.
D-382A marker written on a call of a module function, such as let t = alias first(alias xs), passes both checkers and runs on the VM and natively, but the interpreter stops with a dynamic failure (first is not declared). The marker belongs on the argument alone.Write let t = first(alias xs): the call lends what its result declares, and no marker is needed on the call.
D-396first() on a list whose element is a class, such as xs.first() on List[Token], does not build natively (rustc E0277, the element is not Clone). The interpreter and the VM run it.Use xs.get(0), which builds, or run it with fortis run or fortisc vm.
D-397I/O through a capability held in a local's field (let d = make(console, ...); d.console.print(...)) passes both checkers and runs on the interpreter, but the VM's IR validation refuses it (the receiver is not derived from a parameter through places) and native code reports that refusal as an internal compiler defect.Print through the capability parameter itself, or a binding made from it directly.
D-399Array.filled with its size taken from the expected type, such as let arr: Array[Int, 3] = Array.filled(7), passes both checkers, and every backend then refuses it.Write the size on the call: Array[Int, 3].filled(7).
D-354An owned optional local of a class with cleanup, written without a marker on the left of a ?? that moves its fallback (let p: Token? = none ?? move d), does not build natively (rustc E0382). The interpreter and the VM run it.Write move none ?? move d, which builds and runs alike on every backend.

Defects carried from v0.0.1#

The checkers accept each of these programs although the Language Reference rejects it, so a checked program can still go wrong. v0.0.1 had every one of them; v0.0.2 is no worse, and each is fixed in the release its record names. Avoid the shape, as the second column says.

DefectWhat you meetWhat to do
D-352Inside a generic function, a loan can be returned or stored as if it were owned: func id[T](x: T) T { return x } and func first[T](xs: List[T]) T? { return xs.get(0) } are accepted, and the caller then holds a second reference to the argument or the list's element.Write the function for the concrete type, where the checkers require copy or reject the loan.
D-355A loan given out of an if or match branch (give xs.get(0)), or lent by a match's scrutinee that is a temporary, such as match xs.get(0), ends with its statement, so the list can be changed while the loan is still in use.Bind the loan with let first (let t = xs.get(0)) and branch or match on t: a let binding holds the loan to the end of its block.
D-356A field read through an optional loan with ?., such as xs.get(0)?.inner, is typed as owned, so a binding of it can change the list's own element on the interpreter and the VM.Treat a value read with ?. through a loan as read-only: do not change it, or a binding made from it. To change a value of your own, build a new one.
D-357An owned optional binding written without a marker on the left of a ?? whose result is owned, as in let p: Token? = some ?? move d, is accepted, so p and some both own the value.Write move some ?? move d, or copy some ?? move d.
D-362A loan held inside an optional by a let mut binding (let mut t = xs.get(0)) is treated as ended after a while or for loop whose body ends it (t = null), although a loop that runs no times, a break or a continue skips that, so the list can be changed while the loan lives.End the loan before the loop (t = null), or keep the loan in a block that ends before the list changes.
D-364A defer that reads a binding of its block holding a loan inside an optional (let t = xs.get(0), then defer { ... t ... }) is accepted, although a deferred block may not use a binding of its block that holds a loan.Read what the deferred block needs before it, into a value of its own (copy), and use that in the defer.
D-369A binding of a ?? whose fallback it owns, such as let t = empty.get(0) ?? move d, is typed as a loan of the list, so it can be stored in a binding of an outer block (keep = present(t)) and read there after the fallback's cleanup has run.Keep such a binding in its own block, or move the fallback into a binding of its own first (let f = move d) and use that.
D-370On the interpreter, an unmarked copy of such a binding, or of a tuple element holding such a value (let a = t, let a = pair.0), becomes a second owner, so the fallback's cleanup runs when the copy ends, before the binding does.Write copy t (or alias t) to say which you mean.
D-375A ?? whose fallback is the statement's own value, lent to a read parameter (show(console, empty.get(0) ?? move d)), is never destroyed on the interpreter or the VM, so its cleanup does not run; native code destroys it when the statement ends.Bind the fallback first (let v = empty.get(0) ?? move d) and pass v, so the binding's end runs its cleanup.
D-376On the interpreter, assigning to a field of a record literal (rec.side = make(...), or a loan over a field that held a value of the record's own) does not run the old value's cleanup, and a loan assigned over such a field is cleaned up with the record while its owner still holds it. The VM runs each cleanup once, at its owner's end.Use a class for a value whose fields are reassigned, or run the program on the VM.
D-379A fn once closure may return a loan from a move capture (fn once[move t]() Token from t { return move t }), which the consuming call destroys: both checkers accept it, the interpreter and the VM keep the value until the receiving binding ends or read it destroyed, and native code refuses the build.Return the captured value itself from a closure returning the owned type, or let the caller keep the binding and lend it to the closure instead of moving it in.
D-388A tuple built around a value of the function's own (let t = (empty.get(0) ?? move d, 1)), bound first and returned inside present as a from result, passes both checkers; the interpreter destroys the value at the call and the caller then reads it destroyed, and the VM never runs its cleanup.Return the owned value from a function returning the owned type, or keep the fallback in a binding of its own (let f = move d) that outlives the result.
D-389Inside a returned match arm, an if giving a loan on one branch and the function's own value on the other (let v = if flag { give x } else { give move d }; give v) passes both checkers, and both running backends destroy the moved value at the call, so later reads see it destroyed.Give every branch a loan, or return the owned value from a function returning the owned type.
D-392A loan taken from a temporary receiver, such as let t = fresh().get(0) (also .first(), ?? make(...), or a cursor of a temporary), passes both checkers; the temporary is destroyed at the statement's end and t then reads the destroyed element on the interpreter and the VM; native refuses the build.Bind the temporary first (let xs = fresh()) and take the loan from the binding.
D-393A pure function may print through a dropped value's cleanup: the io of a cleanup is not attributed to the function that drops the value, so both checkers accept it and every backend prints.Do not drop a value whose cleanup does I/O inside a function declared pure; give the value to the caller.
D-394A lent match payload (match xs.get(0) { present(x) => ... }) is destroyed at the arm's end on the interpreter, and on the VM for a plain optional, rather than at its owner's end, so a read of the element after the match sees it destroyed; native is right.Read what you need inside the arm, or bind the loan first (let t = xs.get(0)) and match on t.
D-395A result declared from one parameter (from xs) that lends another (ys) is rejected for a direct return but not through give, a match expression or an expression body, so the loan is recorded against the wrong owner and ys can change while the result lives.Declare the result from the parameter it lends, and return it directly.
D-413On the VM, an owned value recovered by a catch expression whose result the statement discards (discard (g() catch e { report e; recover make(...) })) is never destroyed, so its cleanup does not run; the interpreter and native code run it. The or recover form, and a catch whose value a let binds, run it on the VM too.Bind the catch's value (let x = g() catch e { ... }), so the binding's end runs the cleanup, or write or recover.
D-414An expect outside a test body, in an ordinary function or in a deferred block, is accepted by both checkers, and a failing one has no defined outcome: the interpreter stops with a Python traceback and writes no record, the VM reports a dynamic check failure, and native code does not build the program.Write expect in test bodies only. In a function, test the condition with if, and fail or return.

What v0.0.2 leaves for later#

DefectWhat you meetWhat to do
The older forms are accepted alongside the new ones, so a reader may meet both until the code is migrated.Run fortis fmt --write on the code. It rewrites each older form where the program means the same.
D-404fortis fmt never rewrites Int.shiftLeft(a, b) or fail to a << b or fail, although the two are the same operation; Int.add, sub, mul, div and rem are rewritten.Write the operator form by hand, or leave the named call. The two mean the same.
fortis fmt does not rewrite a logging call, add @ignorable or derive Default, or rewrite a main that reads its Capabilities record other than field by field (a capability inside an interpolation, or the record moved whole).Make those changes by hand. Each is the author's choice.
D-406fortis fmt keeps a pure or noalloc written on a lambda, although the function type the lambda is passed to already states it; it prints no inferred one.Remove the modifier by hand if you want the shorter form. It changes nothing the checker decides.
Checked operators cover Int only. The sized integer types (Int32, UInt8 and the rest) have no checked, wrapping or saturating operations yet; they are planned for v0.4.Give the operands a refined type, or test them first, so that the operation is proved. Or compute in Int.
fortis fmt prints a module's inferred facts back only when the module checks on its own, so a module of a package that needs the rest of its package to check is not given them.Nothing changes in what the program means; the checker infers the facts either way. Write a fact by hand where you want it shown.
