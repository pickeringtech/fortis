Agent mode: Ownership (LR 7)

Ownership#

Human mode. Agent mode: Ownership, by rule. Source of truth: LR 7.

Every value in Fortis has exactly one owner, and every other use of it is either a loan or a transfer that the line says out loud. Assigning an existing ownership-bearing value, or passing it where the callee takes ownership, writes copy, alias or move; handing a value to a function that changes it writes editable, and a value that changes is declared let mut (LR 1, LR 7.5). Passing a value to an ordinary parameter needs no marker, because it is a read loan for the call, and a trivial value, such as an integer, never needs one (LR 7.5, LR 6.11). There are no hidden clones and no hidden reference counts, so a reader can answer "who owns this, and can this call change it?" from the line and the declarations it names. The rules are close to Rust's borrow checking, made lexical and written into the source; this chapter introduces them one at a time.

The idea in one paragraph#

The checker follows, for every binding, its type, whether it is mutable, whether it still owns its value or has had it moved out, and which loans of it are active. Every expression is checked against that environment and records the loans it creates, the effects it has and the obligations it leaves behind; written formally, Γ ⊢ e : τ ▷ L, E, O (LR 7.1). It is a finite dataflow analysis over the function's control flow, with no solver, so its answers are predictable: each rejection names a place, a conflicting loan or move, and both positions.

Places and owners#

A place is a path to storage: a binding (invoice), a field path from a binding or from self (invoice.lines, self.status), or an Array element at a literal index (grid[3]). Nothing else is a place: a call result, a ?? b, a literal or list[i] with a variable i are values (LR 7.2). The ownership markers copy, alias, move and editable apply only to places.

A let binding owns the value it was initialised with until the value is moved out, and drops it at the end of its block if it still owns it. A parameter is a binding that can never be reassigned: an owned parameter owns its argument, a plain or editable one holds a loan (LR 7.2).

There are no partial moves: you cannot move one field out of a value and keep the rest (E-OWN-040, LR 7.2). Move the whole value, or take it apart with a consuming pattern (Classes).

Fortis
// reject: E-OWN-040
class Order {
  export id: Int
  export lines: List[String]
}

func keep(lines: owned List[String]) Int => lines.count()

func main() {
  let order = Order(id: 1, lines: List.of("tea"))
  discard keep(move order.lines)      // reject: E-OWN-040
}

Moves#

move p transfers ownership out of p. Afterwards p is uninitialised on that path: reading it, loaning it, moving it again or dropping it is E-OWN-020, use after move (LR 7.4). Where two paths join, a place counts as initialised only if it is initialised on both. A let mut binding can be given a new value after a move.

Fortis
// reject: E-OWN-020
func consume(items: owned List[Int]) Int => items.count()

func main() {
  let items = List.of(1, 2, 3)
  discard consume(move items)
  discard items.count()              // reject: E-OWN-020
}
Fortis
// accept
import fortis.host { Console }

func consume(items: owned List[Int]) Int => items.count()

func main(console: Console) {
  let mut items = List.of(1, 2, 3)
  let n = consume(move items)
  items = List.of(4)
  console.print("consumed ${n}, now ${items.count()}")
}
output
consumed 3, now 1

Markers and where they are needed#

The four markers say how a place is used; they are not operations on values (LR 7.5):

MarkerMeaningAllowed when
copy pan independent duplicatethe type is copyable; refused in noalloc code if it allocates
alias pa read loanalways
editable pan exclusive loanp is rooted in a let mut, an editable parameter or an exclusive loan
move ptransfer ownershipp owns its value and nothing borrows it

Where a marker is needed depends on the position. In short (LR 7.5):

PositionAn existing ownership-bearing place needs
let x = p, x = p, a field initialiser name: p, return pcopy, alias or move
return x of a local let or let mut bindingnothing: nothing can use x afterwards, so the return moves it
argument to a plain parameter, receiver of a self methodnothing: an implicit read loan for the call
argument or receiver that the result borrows fromalias p (or editable p)
receiver of an editable self method, a call of a fn mut closurenothing: p.method(…), bump(), where editable p is allowed
receiver of an owned self methodmove p.method(…)
argument to an editable parametereditable p
argument to an owned parametermove p or copy p
a capture in a closure's capture lista marker (LR 8.3)
operands of ==, < and friends, interpolation, match p, for x in pnothing: an implicit read loan

A fresh value (a literal, a constructor call, a function result, arithmetic) never needs a marker, and neither does a trivial value such as an Int (LR 7.5, LR 6.11). A receiver that a method changes needs none either: the call readings.push(40) is accepted only where readings may change (a let mut binding, an editable parameter or capture, an exclusive loan, or the method's own editable self), so its declaration already says so, and the call takes the same exclusive loan editable readings.push(40) would (LR 7.5). Older code writes the marker; it is still accepted, and fortis fmt drops it. Forgetting a marker where one is required is E-OWN-001 (LR 7.5):

Fortis
// reject: E-OWN-001
class User {
  export name: String
}

func main() {
  let user = User(name: "Ada")
  let other = user                   // reject: E-OWN-001
}

The checker cannot guess which of the three you meant, and each means something different, so it asks:

Fortis
// accept
import fortis.host { Console }

class User {
  export name: String
}

func main(console: Console) {
  let user = User(name: "Ada")
  let duplicate = copy user
  let reader = alias user
  console.print("${duplicate.name} ${reader.name}")
  let taken = move duplicate
  console.print(taken.name)
}
output
Ada Ada
Ada

copy of a value whose type is not copyable, such as a Shared handle, is E-OWN-002 (LR 7.5).

Loans are lexical#

A loan is a reference to a place, either read-only (alias) or exclusive (editable). Loans last for a lexical region, never "until last use" (LR 7.3):

  • a loan held by a binding (let r = alias p, let r = editable p) lasts until the end of the block that declares r;
  • a loan taken for a call's argument or receiver ends when the call returns, unless the result carries it;
  • a loan taken by a comparison, interpolation or capture ends with the statement, and one taken by a for header lasts for the whole loop;
  • a loan taken for an argument of an async call is held by the future the call returns;
  • a loan returned with from is held by whatever binding receives it.

To end a loan early, close a block around it (LR 7.3).

The aliasing invariant. At any point an owner has either one active exclusive loan or any number of read loans, never both. An exclusive loan of any field freezes the whole owner, while read loans of different fields coexist. While a loan is active the owner may not be moved, dropped or reassigned, and under a read loan not mutated. A conflicting loan is E-OWN-010; using an owner while it is loaned is E-OWN-011 (LR 7.3).

Fortis
// reject: E-OWN-010
class Invoice {
  export customer: Int
  export lines: List[String]
  export func issue(editable self) {
    self.customer = 0
  }
}

func main() {
  let mut invoice = Invoice(customer: 7, lines: List.of("tea"))
  let customer = alias invoice.customer
  let lines = alias invoice.lines
  invoice.issue()                          // reject: E-OWN-010
}

The two read loans of different fields are fine together; the exclusive loan invoice.issue() takes is not, while they are alive. Putting the reads in their own block ends them before the call:

Fortis
// accept
import fortis.host { Console }

class Invoice {
  export customer: Int
  export lines: List[String]
  export func issue(editable self) {
    self.customer = 0
  }
}

func main(console: Console) {
  let mut invoice = Invoice(customer: 7, lines: List.of("tea"))
  {
    let lines = alias invoice.lines
    console.print("${lines.count()} line")
  }
  invoice.issue()
  console.print("customer now ${invoice.customer}")
}
output
1 line
customer now 0

Loans through loans. A binding that holds a loan (a plain or editable parameter, or let r = alias p) is a path to the owner, and every loan is recorded against the owner (LR 7.3). Reading through an exclusive parent creates a read child that freezes the parent; taking an exclusive child suspends the parent entirely until the child ends. A loan-holding binding can never be reassigned, except a let mut binding of a standard cursor, which owns the cursor value (LR 7.7): the reassignment destroys the old cursor, the loan it stored ends (LR 7.9), and the binding holds the new cursor's loan to the end of its block (D-401).

Fortis
// reject: E-OWN-011
class Cell {
  export value: Int
}

func inspect(c: Cell) Int => c.value

func use(c: editable Cell) {
  discard inspect(c)           // a read child of the exclusive parent, ended when inspect returns
  let r = editable c           // an exclusive child held by r: c is suspended until the block ends
  r.value = 1
  discard c.value              // reject: E-OWN-011
}

func main() {
}

Parameters, receivers and returns#

A parameter's mode says what the callee may do, and the call site repeats it (LR 7.6):

ParameterCaller writesCallee holds
x: T (ownership-bearing)the place, unmarkeda read loan for the call
x: editable Teditable pan exclusive loan for the call
x: owned Tmove p, copy p or a fresh valueownership
x: T (trivial)the valuea copy

editable gives permission to change the referent, not to rebind the parameter: parameters are never reassignable (LR 7.6). Methods declare their receiver the same way, self, editable self or owned self: invoice.render() reads, invoice.issue(now) changes invoice, which must therefore be declared where it may change, and move invoice.archive() consumes it. A reviewer sees at every call whether the receiver is consumed, and at its declaration whether it can change (LR 7.5, LR 7.6).

Fortis
// accept
import fortis.host { Console }

class Counter {
  export value: Int<0..1000>
  export func bump(editable self) {
    if self.value < 1000 {
      self.value = self.value + 1
    }
  }
  export func finish(owned self) Int => self.value
}

func show(c: Counter) Int => c.value

func main(console: Console) {
  let mut counter = Counter(value: 0)
  counter.bump()
  counter.bump()
  console.print("shown ${show(counter)}")
  console.print("finished at ${move counter.finish()}")
}
output
shown 2
finished at 2

Returning a loan. A function that returns a loan names where it comes from with from, which names exactly one plain or editable parameter (or self) (LR 7.6). At the call, the argument the result borrows from is marked with alias (or editable for an exclusive parameter), because that loan now outlives the statement: it is held by the binding that receives the result.

Fortis
// accept
import fortis.host { Console }

class User {
  export name: String
}

pure func displayName(user: User) StringView from user {
  return alias user.name
}

func main(console: Console) {
  let user = User(name: "Ada Lovelace")
  let name = displayName(alias user)
  console.print("${name} has ${name.scalarCount()} scalars")
}
output
Ada Lovelace has 12 scalars

The returned loan has the mode the signature declares: StringView from user is a read loan, and editable Cell from c is an exclusive one, allowed only when c is itself editable, which suspends the caller's c while the result lives (LR 7.6). A loan of a local or of a temporary cannot be returned, since it would outlive its owner (E-OWN-051), and a result may name only one origin (E-OWN-050): return an owned value or split the function (LR 7.6). For the same reason a function whose result is declared from a parameter cannot return a value of its own: return xs.get(0) ?? move d, return move d, a fresh value, a tuple or record built around one (return (xs.get(0) ?? move d, 1)) or a match or if one of whose arms gives one would leave the caller holding a loan of a value that ended with the call (E-OWN-051). What produces a from result must lend: a place read through a loan, alias p, a call whose result lends, or a ??, if or match all of whose results do. Bind the loan and return an owned value from a function returning Token, let v = xs.get(0) then return copy v ?? move d, or lend on every path.

Fortis
// reject: E-OWN-051
class User {
  export name: String
  export pure func guest() User => User(name: "guest")
}

pure func displayName(user: User) StringView from user {
  return alias user.name
}

func main() {
  let name = displayName(User.guest())        // reject: E-OWN-051
}
Fortis
// reject: E-OWN-050
class User {
  export name: String
}

pure func longer(a: User, b: User) StringView from a {
  if a.name.scalarCount() > b.name.scalarCount() {
    return alias a.name
  }
  return alias b.name                         // reject: E-OWN-050
}

func main() {
}

To hand back a local you own, return it: return local moves it, since nothing can use it afterwards (LR 7.5). Older code writes return move local; it is still accepted, and fortis fmt drops the move. To hand back a field of a value you only borrow, return copy obj.field or use a from signature; a fresh expression needs no marker (LR 7.6).

A loan stays a loan. xs.get(0) lends the list's element, so returning it as an owned Item?, binding it to an owned type, storing it in a field or passing it owned needs copy: bind the loan and copy what it lends, let first = xs.get(0) then return copy first, or match it, present(w) => copy w. Without the copy the checker reports E-OWN-001; for a value that cannot be copied, such as a Shared, it reports E-OWN-002, and the value stays lent or is taken out of its owner (LR 7.6). A ?? over a loan is a loan too: a read parameter name is returned as return copy name ?? "guest".

The binding that holds such a loan keeps the list lent until its block ends, like any other loan (LR 7.3). After let first = xs.get(0), the list cannot change or move in that block: xs.pop() is E-OWN-010 and move xs is E-OWN-011. Close a block around the loan, or copy what it lends, before changing the list. An element of a trivial type, such as an Int in a List[Int], is copied out and holds nothing.

Views, cursors and no stored loans#

StringView, BytesView, ListView[T] and the cursors of the standard collections are loan-carrying types: values that store a read loan of their origin (LR 7.7). A loan lives in exactly three places: a local binding, a parameter, or a result that names its origin with from. It is never stored in a field. A class may not declare a lifetime parameter, and no field may have a loan type or a loan-carrying type other than one from static; both are E-OWN-053 (LR 7.7, X-137).

Fortis
// reject: E-OWN-053
class Line {                        // reject: E-OWN-053
  export number: Int
  export text: StringView
}

func main() {
}

Store the text itself instead, own it with move or copy, hold it through an explicit Shared, or pass it to each call that needs it (LR 7.7). A parser that would keep a view of its input keeps offsets into it.

Fortis
// accept
import fortis.host { Console }

class Line {
  export number: Int
  export text: String
}

func main(console: Console) {
  let line = Line(number: 1, text: "first")
  console.print("${line.number}: ${line.text}")
}
output
1: first

Leaving stored loans out keeps every loan's lifetime visible in one function, and adding them later would break no program, whereas removing them after a release would (LR 7.7).

Shared ownership#

When a value really must have several owners, Shared[T] is a reference-counted owner, and the cost is written where it happens (LR 7.8):

OperationGivesMeaning
Shared.create(move value)Shared[T]takes ownership; one strong handle
s.retain()Shared[T]another strong handle; the only way to duplicate one, since copy is refused
s.downgrade()Weak[T]a handle that does not keep the value alive
w.upgrade()Shared[T]?a strong handle while one still exists, null afterwards
w.retain()Weak[T]another weak handle

Reading through a Shared[T] is a read loan of the value (s.field, s.method()); a Shared gives read access only, so mutation needs a Mutex or an atomic (LR 7.8, LR 12.7). retain and downgrade have no effects, so a pure function may create and pass handles; upgrade is nondet, because its answer depends on whether another task has dropped the last strong handle (LR 7.8). Cycles of Shared handles leak and the checker does not detect them; a back-reference uses Weak.

Fortis
// accept
import fortis.host { Console }

class Settings {
  export name: String
}

func main(console: Console) {
  let first = Shared.create(Settings(name: "production"))
  let second = first.retain()
  let weak = second.downgrade()
  console.print("${first.name} and ${second.name}")
  match weak.upgrade() {
    present(again) => console.print("still alive: ${again.name}")
    null => console.print("gone")
  }
}
output
production and production
still alive: production
Fortis
// reject: E-OWN-002
class Settings {
  export name: String
}

func main() {
  let first = Shared.create(Settings(name: "production"))
  let second = copy first                     // reject: E-OWN-002
}

A Shared of a capability carries the capability, which is how several values hold one console: see the example under destruction below and LR 11.6.

Destruction#

A value is destroyed at exactly one of these events (LR 7.9):

EventOrder
block exitthe block's loans end, then its defers run last-first, then its locals are dropped in reverse order of initialisation
assignment to a let mut ownerthe new value is evaluated, then the old value is dropped, then the store
temporariesat the end of the statement, in reverse order of creation
break, continue, return, faileach block left, innermost first, in block-exit order
a failed constructor functionthe locals it initialised, in reverse order
a class valueits own cleanup method if it declares one, then its fields in declaration order

A linear value is never destroyed implicitly: the obligation rules make that unreachable (LR 7.9). The order is the same on every backend (LR 7.9):

Fortis
// accept
import fortis.host { Console }

class Resource {
  export id: Int
  export console: Shared[Console]
  cleanup(editable self) {
    self.console.print("release ${self.id}")
  }
}

func work(console: Shared[Console]) {
  let first = Resource(id: 1, console: console.retain())
  let second = Resource(id: 2, console: console.retain())
  console.print("working")
}

func main(out: Console) {
  let console = Shared.create(move out)
  work(console)
  console.print("done")
}
output
working
release 2
release 1
done

second was initialised last, so it is dropped first. main takes the console out of the capabilities with a consuming pattern and puts it behind a Shared, because a field may not hold a loan of it (LR 7.7, LR 11.6).

Only an owner destroys. A binding that holds a loan, such as let t = xs.get(0), let a = alias first or a parameter that is not owned, ends without destroying anything, so a class's cleanup runs once, when its owner is destroyed. A value moved to a new owner is cleaned up there, once (LR 7.9).

The Rust-expressible subset#

The ownership rules were chosen so that every accepted program has a lowering to safe Rust, listed shape by shape in LR Appendix C (LR 7.10). A situation the checker can describe but that has no such shape, for example a loan stored inside a Shared, is rejected with E-OWN-053 and a pointer to the nearest supported pattern; it is never lowered with unsafe (LR 7.10, LR C.2).

Fortis
// reject: E-OWN-053
class User {
  export name: String
}

pure func displayName(user: User) StringView from user => alias user.name

func run(user: User) Int {
  let seen = displayName(alias user)
  let shared = Shared.create(move seen)    // reject: E-OWN-053
  return shared.scalarCount()
}

func main() {
}

Widening the subset is a language change with a recorded decision, never an implementation shortcut, and the checker never inserts a clone, a reference count or hidden sharing to rescue a rejected program (LR 7.10).

Collections store values (LR 7.7)#

An owned collection cannot store a non-static loan, even when the collection itself is local (E-OWN-053). The rule covers elements, keys and values, optional and aggregate contents, outcomes, newtype representations and storing generic arguments. List[T] is valid generic code only when every instantiation meets that rule. An explicit StringView from static is exempt, but the source must prove that origin; an annotation cannot turn a local view into a static one. A plain StringView is not the exception even if its initial value is a literal (LR 7.7).

Fortis
// reject: E-OWN-053
func main() {
  let text: String = " tea "
  let pieces = List.of(text.trim())          // reject: E-OWN-053
}
Fortis
// accept
func size() Int {
  let text: String = " tea "
  let pieces = List.of(text.trim() as String)
  return pieces.count()
}
test "store owned text" {
  expect size() == 1
}

A view of an owned temporary cannot survive its statement (E-OWN-051, LR 7.6, LR 7.9). This includes a receiver that owns a value on only one branch of ??, if, match or recovery. Bind the owner first, then take the view; a view used only within the statement is allowed.

Fortis
// reject: E-OWN-051
func main() {
  let trimmed = (" tea " as String).trim()   // reject: E-OWN-051
}
Fortis
// accept
func size() Int {
  let text: String = " tea "
  let trimmed = text.trim()
  return trimmed.scalarCount()
}
test "the owner outlives its view" {
  expect size() == 3
}

A scalar result carries no loan from its operands (LR 7.6; X-714). Returning a.trim().scalarCount() gives an Int without a loan of a, and comparing trimmed views gives a Bool without one. Returning a.trim() still lends from a and needs the declared origin. Other operands of an enclosing expression keep their own loans.
