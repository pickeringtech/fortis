Human mode: Cleanup, async and concurrency

Cleanup, async and concurrency (LR 12)#

Agent mode. Human mode: Cleanup, async and concurrency. Source of truth: LR 12.

Preview: async, cancellation, scopes and sharing (LR 12.3, 12.4, 12.5, 12.6 and 12.7) arrive in v0.3. defer and destruction order (LR 12.1, 12.2) are in v0.0.1.

Rules#

LANG-12-01A defer body is checked as if written at every exit of its block (after the block's own loans end, before its locals drop); it cannot alter the outcome; the places it names are initialised at every exit.LR 12.1
LANG-12-02Failures produced inside a defer are consumed there (or recover, catch … recover, report) and never replace the primary outcome; cleanup reports are labelled as such.LR 12.1
LANG-12-03Future and Task are linear; a pending future is never destroyed; cancellation is observed only at cancellation points.LR 12.3, 12.4
LANG-12-04A scope joins or cancels every task it launched before its block exits.LR 12.5
LANG-12-05Only Shareable environments without loans cross launchParallel/launchBlocking; loans cross only cooperative launch within the owner's block.LR 12.5, 12.7
LANG-12-06A MutexGuard is never live across await.LR 12.3, 12.7

Exit and destruction order (LR 12.2, LR 5.1, LR 7.9)#

At every block exit, including cancellation and or fail:

  1. the block's loans end; tasks launched on a scope declared in the block are cancelled and joined (their carried loans end) (LR 12.4, LR 12.5);
  2. deferred blocks run, last registered first (LR 12.1);
  3. during an unwind (cancellation or fail), abandon runs on every live Abandonable local, reverse initialisation order (LR 12.4);
  4. owned locals drop, reverse initialisation order; a class value runs its cleanup, then drops its fields in declaration order (LR 7.9).

defer constraints (LR 12.1)#

  • Block form only; no return, fail, give, break, continue, await inside (E-DEF-001); defer await is not in v1.
  • Places it names must be initialised at every exit: no move of them between the defer and an exit (E-DEF-002).
  • It may not use a binding of its own block that holds a loan (E-OWN-052); loans of enclosing blocks still apply.
  • Its effects join the function's summary; a silent recovery inside it adds recovers.

Async model (LR 12.3, LR 12.4)#

  • async func f(…) T call: evaluates arguments, returns Future[T] (Future[Outcome[T]] with try); the body starts at the first await or at launch.
  • await e: only directly in an async body (not in a non-async lambda, not in defer).
  • Future[T] is linear: await, launch, or discard. discard only for a never-polled future whose environment holds no linear value and no exclusive loan; it emits a not_started record.
  • A future holds its arguments' loans (LR 7.3).
  • Cancellation points: await (cooperative); await and checkpoint() (parallel and blocking pools). Cancellation is not a failure: not catchable, recoverable or matchable.
  • No linear value live across a cancellation point unless it implements Abandonable (func abandon(owned self): synchronous, non-failing, non-suspending). An Abandonable local may also be live at or fail (the unwind abandons it); a normal exit must still consume it. Task implements it.
  • The futures and tasks being awaited are not "live across" their own await.

Launch forms (LR 12.5)#

FormExecutorEnvironment
s.launch(f) → Task[T]same cooperative executor and threadmay borrow any binding declared in or before the scope
s.launchParallel(f) → Task[T]CPU worker poolShareable, no loans; cancellation at await and checkpoint()
s.launchBlocking(work) → Task[T]bounded blocking poolwork: fn once() T, Shareable environment; the only place block is allowed in async code; cancellation at checkpoint()
s.detach(move task, supervisor)—moves the join obligation to a Supervisor; removes the task from the scope
join(a, b) → (A, B)polled inside the parentconsumes both futures; loans allowed; never returns early; failures stay in the tuple

A Task is awaited inside its scope or detached. A scope exiting by fail, return, break or cancellation cancels and joins its running tasks before its deferred blocks run; results never awaited are consumed by the scope (a failure inside one is reported, labelled as abandoned by the scope) (LR 12.5).

TaskCompletion[T] = Completed(value: T) | Cancelled(reason: Cancellation) | Defect(info: TaskDefect); observed only by the supervisor of a detached task; linear when T is; consumed with match (LR 12.6).

Shareable (LR 12.7)#

  • Shareable: trivial types; String, Bytes, BigInt; List, Array, Map, OrderedMap, Set, FixedList, FixedMap of shareables; classes, enums, tuples and records whose fields are all shareable; Shared[T], Weak[T], Mutex[T] with T: Shareable; AtomicInt, AtomicBool; fn / fn once closures capturing only copy/move of shareables; capability values.
  • Not shareable: loans and views, MutexGuard, fn mut closures, Future, Task, thread-bound resources.

List.of("a", "b") is a List[StringView] (views of static text), which is not Shareable; annotate let words: List[String] = … to make owned strings (LR 3.5, LR 12.7).

Mutation between tasks: Mutex[T]. Async: await m.lock(); sync: m.lockBlocking() (block). Both return Outcome[MutexGuard[T]] from mutex; the guard is an exclusive loan of T, not Shareable, unlocks when destroyed, and cannot cross await. Atomics: AtomicInt, AtomicBool (LR 12.7).

Correction patterns#

E-DEF-001: or fail inside defer (LR 12.1)#

Fortis
// reject: E-DEF-001
export error FlushFailed {
  code: "demo.flush"
}

try func flush() {
  fail FlushFailed()
}

try func work(n: Int) Int {
  defer {
    flush() or fail                   // reject: E-DEF-001
  }
  return n
}

test "work" {
  expect work(1) == 1
}
Fortis
// accept
export error FlushFailed {
  code: "demo.flush"
}

try func flush() {
  fail FlushFailed()
}

func work(n: Int) Int {
  defer {
    flush() catch e {
      report e
      recover Void
    }
  }
  return n
}

test "work" {
  expect work(1) == 1
}

Facts used when writing code#

  • main may be async func main or async try func main; it runs as the root task on the core cooperative executor (LR 4.6).
  • await first or fail leaving a scope cancels the other tasks of that scope; a task cancelled before its first poll never runs (LR 12.5).
  • The v1 executor runs every cooperative task of one scope tree on one thread; launch never needs Shareable (LR 12.5).
  • Shared[T] gives read access only; mutation goes through Mutex[T] or an atomic (LR 7.8, LR 12.7).
  • No cross-backend agreement is claimed for interleaving timing; write output after awaits in a fixed order (LR 12.7).
