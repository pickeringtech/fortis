Human mode: Statements and expressions

Statements and expressions (LR 5)#

Agent mode. Human mode: Statements and expressions. Source of truth: LR 5.

Rules#

RuleStatementLR

LANG-05-02Every block exit (fall-through, return, fail, break, continue, give) ends the block's loans, runs its defers LIFO, then drops its owned locals in reverse initialisation order.LR 5.1
LANG-05-03if and while conditions are Bool; nothing else converts.LR 5.2

LANG-05-05A non-Void function ends every path in return, fail or a Never call; no implicit value.LR 5.4
LANG-05-06Precedence and associativity follow the LR 5.6 table; outcome operators (or fail, or recover, catch), ?? and &&/|| do not mix without parentheses.LR 5.6
LANG-05-07Operands and arguments evaluate left to right, once; receiver before arguments; calls run evaluate, activate, invoke, release.LR 5.7

Correction patterns#

E-NAM-002: assignment to an immutable binding (LR 5.1)#

Fortis
// reject: E-NAM-002
pure func next(n: Int<0..9>) Int {
  let x = n
  x = n + 1                 // reject: E-NAM-002
  return x
}

test "next" {
  expect next(1) == 2
}
Fortis
// accept
pure func next(n: Int<0..9>) Int {
  let mut x: Int<0..10> = n
  x = n + 1
  return x
}

test "next" {
  expect next(1) == 2
}

E-TYP-010: non-Bool condition (LR 5.2)#

Fortis
// reject: E-TYP-010
pure func describe(n: Int) StringView from static {
  if n {                    // reject: E-TYP-010
    return "non-zero"
  }
  return "zero"
}

test "describe" {
  expect describe(0) == "zero"
}
Fortis
// accept
pure func describe(n: Int) StringView from static {
  if n != 0 {
    return "non-zero"
  }
  return "zero"
}

test "describe" {
  expect describe(0) == "zero"
  expect describe(3) == "non-zero"
}

E-TYP-110: a path without return (LR 5.4)#

The record is reported at the function head.

Fortis
// reject: E-TYP-110
pure func sign(n: Int) Int {        // reject: E-TYP-110
  if n < 0 {
    return -1
  }
}

test "sign" {
  expect sign(-4) == -1
}
Fortis
// accept
pure func sign(n: Int) Int {
  if n < 0 {
    return -1
  }
  if n == 0 {
    return 0
  }
  return 1
}

test "sign" {
  expect sign(-4) == -1
  expect sign(0) == 0
  expect sign(9) == 1
}

E-TYP-120: give outside an if expression or arm (LR 5.4)#

Fortis
// reject: E-TYP-120
pure func pick(flag: Bool) Int {
  if flag {
    give 1                  // reject: E-TYP-120
  }
  return 0
}

test "pick" {
  expect pick(false) == 0
}
Fortis
// accept
pure func pick(flag: Bool) Int {
  return if flag { give 1 } else { give 0 }
}

test "pick" {
  expect pick(true) == 1
  expect pick(false) == 0
}

E-TYP-140: unused value (LR 5.5)#

Fortis
// reject: E-TYP-140
pure func double(n: Int<0..1000>) Int => n * 2

test "double" {
  double(4)                 // reject: E-TYP-140
  expect double(2) == 4
}
Fortis
// accept
pure func double(n: Int<0..1000>) Int => n * 2

test "double" {
  discard double(4)
  expect double(2) == 4
}

E-SYN-004: mixed operator families (LR 5.6)#

Fortis
// reject: E-SYN-004
pure func choose(a: Bool, b: Bool?, c: Bool) Bool {
  return a || b ?? c        // reject: E-SYN-004
}

test "choose" {
  expect choose(false, null, true)
}
Fortis
// accept
pure func choose(a: Bool, b: Bool?, c: Bool) Bool {
  return a || (b ?? c)
}

test "choose" {
  expect choose(false, null, true)
  expect !choose(false, false, true)
}

E-OWN-012: a reservation broken by a later argument (LR 5.7)#

Fortis
// reject: E-OWN-012
class Buffer {
  export bytes: Int
}

func update(target: editable Buffer, size: Int) {
  target.bytes = size
}

func consume(b: owned Buffer) Int => b.bytes

test "update" {
  let mut buffer = Buffer(bytes: 0)
  update(editable buffer, consume(move buffer))   // reject: E-OWN-012
  expect buffer.bytes == 0
}
Fortis
// accept
class Buffer {
  export bytes: Int
}

func update(target: editable Buffer, size: Int) {
  target.bytes = size
}

func size(b: Buffer) Int => 7

test "update" {
  let mut buffer = Buffer(bytes: 0)
  let n = size(buffer)
  update(editable buffer, n)
  expect buffer.bytes == 7
}

E-TYP-130 and E-TYP-050: argument binding (LR 5.8)#

Fortis
// reject: E-TYP-130
pure func area(width: Int<0..100>, height: Int<0..100>) Int => width * height

test "area" {
  expect area(width: 2, depth: 3) == 6    // reject: E-TYP-130
}
Fortis
// reject: E-TYP-050
pure func area(width: Int<0..100>, height: Int<0..100>) Int => width * height

test "area" {
  expect area(width: 2) == 6              // reject: E-TYP-050
}
Fortis
// accept
pure func area(width: Int<0..100>, height: Int<0..100>) Int => width * height

test "area" {
  expect area(2, height: 3) == 6
  expect area(height: 3, width: 2) == 6
}

@ignorable instead of discard (LR 5.5)#

A function whose result most callers do not need is declared @ignorable once, and its call statements drop the result without discard (LR 5.5, X-345). A linear result can never be ignorable (E-TYP-150).

Fortis
// accept
@ignorable
func remember(seen: editable Set[Int], n: Int) Bool {
  return seen.add(n)
}

test "remember" {
  let mut seen: Set[Int] = Set.default()
  remember(editable seen, 4)
  expect seen.count() == 1
}

Facts used when writing code#

  • Literal booleans, if expressions and match give values; if without else is a statement only (LR 5.2).
  • Ranges a..b (inclusive) and a..<b (exclusive) exist only in for headers and refinement types (LR 5.6).
  • for x in p takes a read loan of p for the loop and binds read loans of the elements; for x in move p consumes p and binds owned elements (LR 5.3).
  • Labels: outer: for …, then break outer / continue outer; break carries no value (LR 5.3).
  • return/fail inside a lambda refer to the lambda; give/recover never cross a function or lambda boundary (LR 5.4).
  • await f() or fail is (await f()) or fail; copy await f() is a parse error: markers take places (LR 5.6).
  • Defaults are pure, non-allocating constant expressions re-evaluated at each call (LR 5.8). No user variadics: take ListView[T] and pass List.of(…) (LR 5.8).
  • Temporaries drop at the end of the full statement in reverse creation order (LR 5.7).
