Human mode: Functions and closures

Functions and closures (LR 8)#

Agent mode. Human mode: Functions and closures. Source of truth: LR 8.

Rules#

RuleStatementLR
LANG-08-01Every parameter has a type and the success type is written, except that a function or method head leaves out Void and a lambda's are inferred as LR 8.2 allows; modifiers in the order [export] [Contract …] [pure] [noalloc] [async] [try] [recovers] func; aspects on the lines above.LR 8.1
LANG-08-02A lambda writes its kind (fn, fn mut, fn once) and its capture list (brackets only when non-empty); a body needing a stronger kind than declared is rejected.LR 8.2
LANG-08-03A name not in the capture list is inaccessible in the lambda body.LR 8.3
LANG-08-04Callable assignability: kind fn ≤ fn mut ≤ fn once; parameter modes match exactly; modifiers at least as strong; an owned closure's region at least as long. The backend boxes a closure only where dynamic fn is written.LR 8.4

Facts#

  • Expression body: func f(x: T) R => expr, exactly one expression (LR 8.1).
  • A Void result is left out of every function and method head, expression bodies and cleanup included: func reset(c: editable Counter) { … }. A function type keeps it (fn(Int) Void), and so does a block-bodied lambda. Older code writes ) Void {; fortis fmt drops it (LR 8.1).
  • A named function is not a value; its name where a callable is expected becomes a non-capturing fn of the matching type (LR 8.1).
  • try, async, recovers must be written when the summary has them (functions and lambdas); pure and noalloc are optional claims, inferred for lambdas; the formatter prints no inferred one back on a lambda and keeps one the author wrote (the callee's function type states them and the checker enforces it there) (LR 8.1, LR 8.2, X-345).
  • Lambda shape below; => expr for an expression body; a block body writes its return type, an expression body may leave it out: it is the callee's (or annotation's) result type when that names one, else the body's type widened as an unannotated let (LR 8.2, X-345); parameter types may be omitted only when passed directly to a parameter of known function type; lambdas are not generic (LR 8.2).

  • Kinds (LR 8.2):
    KindCaptures may beCallBindingLowers to
    fncopy, alias, move (read-only use)f(x)letFn

  • A fn mut call needs no editable where the binding shows it may change (let mut, an editable parameter or capture), and is checked as the marked call; through a let it is E-OWN-001, marked or not. Older code writes editable f(x) (LR 8.2, LR 7.5).
  • A move capture alone does not require fn once; moving the captured value out does (LR 8.2).
  • Capture entries: copy x, alias x, editable x, move x; a trivial value may be bare ([n] = copy). Evaluated left to right when the lambda is evaluated. Module consts, functions and types are not captures (LR 8.3).
  • Capturing a field path (alias self.lines) captures that path and loans the root owner for the closure's lifetime; two editable captures of one owner, or editable plus any other capture of it, conflict (LR 8.3).
  • A loan-holding closure passed to a plain fn parameter is a read loan for the call: no region in the type. Owned positions (owned fn parameter, return) must name its region: fn(Int) Bool from limit; a field never holds one (LR 8.3, LR 7.7).
  • A closure capturing a linear value by move is linear: it must be fn once and be called exactly once on every path, or passed to an owned fn once parameter (LR 8.3).
  • fn() (StringView from s) from s: when the result is loan-carrying, from after it belongs to the result; the closure's own region goes on a parenthesised result (LR 8.4).
  • dynamic fn(…) R: boxed, owned, allocates on creation; the only way to hold closures of different concrete types in one collection (LR 8.4).

E-FUN-011a name used in the body is not in the capture listadd the capture with the right markerLR 8.3
E-OWN-010two captures of one owner where one is editablecapture once, or narrow to disjoint field paths read-onlyLR 8.3
E-OBL-006a fn or fn mut captures a linear value by movedeclare fn once and call it once with move f()LR 8.3
E-OWN-001a fn mut called through a binding that cannot change (a let), marked or not; a fn once call without movehold the fn mut in a let mut and call f(…); write move f(…)LR 7.5
E-OWN-020a fn once called a second time (the first call moved it)call it once; restructureLR 7.4
E-OWN-011a captured place used while the closure holds an exclusive loan of itend the closure's block before using the placeLR 8.3

Modifiers appear in exactly the order of LR 8.1; any other order is a canonicalisation error that the formatter fixes (LR 8.1). Today's tools disagree with that rule: both checkers report an out-of-order head as E-SYN-000 (LR 3.2) and fortis fmt refuses the file, a disagreement recorded in X-153 and D-59. Write modifiers in order.

Correction patterns#

E-FUN-010: kind too weak (LR 8.2)#

Fortis
// reject: E-FUN-010
func countCalls() Int {
  let mut calls = 0
  {
    let bump = fn[editable calls]() Void {
      calls = Int.saturatingAdd(calls, 1)        // reject: E-FUN-010
    }
  }
  return calls
}

test "calls" {
  expect countCalls() == 0
}
Fortis
// accept
func countCalls() Int {
  let mut calls = 0
  {
    let mut bump = fn mut[editable calls]() Void {
      calls = Int.saturatingAdd(calls, 1)
    }
    bump()
    bump()
  }
  return calls
}

test "calls" {
  expect countCalls() == 2
}

Fortis

  return items.countWhere(fn[limit](n: Int) Bool => n > limit)

E-OWN-001: fn mut called through a binding that cannot change (LR 7.5, LR 8.2)#

A fn mut held by a let mut binding is called as add(item); held by a let, it cannot be called at all.

Fortis
// reject: E-OWN-001
func sum(items: List[Int]) Int {
  let mut total = 0
  {
    let add = fn mut[editable total](n: Int) Void {
      total = Int.saturatingAdd(total, n)
    }
    for item in items {
      add(item)                                   // reject: E-OWN-001
    }
  }
  return total
}

test "sum" {
  expect sum(List.of(1, 2, 3)) == 6
}
Fortis
// accept
func sum(items: List[Int]) Int {
  let mut total = 0
  {
    let mut add = fn mut[editable total](n: Int) Void {
      total = Int.saturatingAdd(total, n)
    }
    for item in items {
      add(item)
    }
  }
  return total
}

test "sum" {
  expect sum(List.of(1, 2, 3)) == 6

E-OBL-006: a linear capture in a repeatable closure (LR 8.3)#

The fn mut below also never consumes what it owns, so its binding is dropped with an obligation: E-OBL-001 on the same line (LR 6.12).

Fortis
// reject: E-OBL-006, E-OBL-001
export error Oops {
  code: "demo.oops"
}

pure try func risky(n: Int) Int {
  if n > 9 {
    fail Oops()
  }
  return n
}

pure recovers func later(n: Int) Int {
  let pending = risky(n)
  let mut run = fn mut[move pending]() Int {        // reject: E-OBL-006, E-OBL-001
    return 0
  }
  return run()
}

test "later" {
  expect later(3) == 3
}
Fortis
// accept
export error Oops {
  code: "demo.oops"
}

pure try func risky(n: Int) Int {
  if n > 9 {
    fail Oops()
  }
  return n
}

pure recovers func later(n: Int) Int {
  let pending = risky(n)
  let run = fn once[move pending]() Int {
    return move pending or recover 0
  }
  return move run()
}

test "later" {
  expect later(3) == 3
  expect later(12) == 0
}

A loan-holding closure in an owned position needs its region (LR 8.3, LR 8.4)#

A returned closure that holds a loan names its region in the return type (fn(Int) Bool from limit); without it the function is rejected (LR 8.3). Which code reports that is not yet settled (X-152): the record names the place and asks for … from limit.

Fortis
// accept
class Limit {
  export value: Int
}

func above(limit: Limit) fn(Int) Bool from limit {
  return fn[alias limit](n: Int) Bool => n > limit.value
}

test "above" {
  let limit = Limit(value: 3)
  let check = above(alias limit)
  expect check(5)
  expect !check(2)
}

Callback purity (LR 8.4)#

A non-pure callable where pure fn is required is a type mismatch (expected_type pure fn(…)).

Fortis
// reject: E-TYP-040
import fortis.host { Console }

pure func applyPure(f: pure fn(Int) Int, x: Int) Int => f(x)

func logged(console: Console, n: Int) Int {
  console.print("called")
  return n
}

func run(console: Console) {
  discard applyPure(fn[alias console](n: Int) Int => logged(console, n), 1)   // reject: E-TYP-040
}

test "run" {
  expect true
}
Fortis
// accept
pure func applyPure(f: pure fn(Int) Int, x: Int) Int => f(x)

pure func double(n: Int) Int => Int.saturatingMul(n, 2)

test "run" {
  expect applyPure(double, 4) == 8
  expect applyPure(fn(n: Int) Int => Int.saturatingAdd(n, 1), 4) == 5
}
