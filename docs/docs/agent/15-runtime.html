Human mode: The core runtime

Core runtime inventory (LR 15)#

Agent mode. Human mode: The core runtime. Source of truth: LR 15.

Preview: the core runtime inventory (LR 15) arrives in v0.4.

LR 15 has no rule table of its own; its components are bound by rules elsewhere: LANG-04-06 (LR 4.6), LANG-11-07 (LR 11.6), LANG-12-04 (LR 12.5), LANG-13-01 (LR 13). A conforming implementation ships these so that a program importing no kit runs; kits add adapters and policy and never replace them (LR 15).

Capabilities and their core operations#

Created once, only for the entry main: the runtime passes each capability main declares as a parameter, by its type (func main(console: Console, fileSystem: FileSystem), LR 4.6), and main lends them to the functions it calls (LR 11.6). Older code calls Host.capabilities() once in a main with no capability parameter; the fields of the returned Capabilities are fileSystem, network, clock, random, environment, process, supervisor, console, secretAccess, rawSql (fortis.host).

Path.parse(text: String) Path is try (LR 15). Per-activation authorities (RequestContext, Identity, Db, Tx, TaskContext, Mail) are minted by their kit's adapter from a capability (LR 15, LR 11.6).

Development adapters of the reference toolchain (library contracts in fortis.host, not language rules): file system rooted in a fresh empty directory per run or FORTIS_DEV_ROOT (relative to the working directory; every backend); network offline except localhost; Random SplitMix64 from seed 0 or FORTIS_DEV_SEED; Process simulates true (0) and false (1); RawSql fails sql.unavailable.

Correction patterns#

E-EFF-010: capabilities created outside main (LR 11.6)#

Fortis
// reject: E-EFF-010
import fortis.host { Host }

func greet() {
  let caps = Host.capabilities()     // reject: E-EFF-010
}

func main() {
  greet()
}
Fortis
// accept
import fortis.host { Console }

func greet(console: Console) {
  console.print("hello")
}

func main(console: Console) {
  greet(console)
}
output
hello

E-EFF-010: Host.capabilities() in a main that takes capabilities (LR 11.6)#

A main with a capability parameter already has its capabilities; a call of Host.capabilities() there is a second creation.

Fortis
// reject: E-EFF-010
import fortis.host { Console, Host }

func main(console: Console) {
  let caps = Host.capabilities()     // reject: E-EFF-010
  console.print("ready")
}
Fortis
// accept
import fortis.host { Console }

func main(console: Console) {
  console.print("ready")
  console.print("once")
}
output
ready
once

Patterns#

Failing try main (exit status 1, one runtime-failure record on stderr naming code, payload and origin; LR 4.6):

Fortis
// accept (exit status 1)
import fortis.host { Path, FileSystem, Console }

try func main(fileSystem: FileSystem, console: Console) {
  let path = Path.parse("missing.txt") or fail
  let text = fileSystem.readText(path) or fail
  console.print(text)
}

Revealing a secret (LR 15):

Fortis
// accept
import fortis.host { reveal, Environment, SecretAccess, Console }

func main(environment: Environment, secretAccess: SecretAccess, console: Console) {
  let home = environment.get("HOME")
  if home != null {
    let value = reveal(home, secretAccess)
    console.print("${value.byteCount() > 0}")
  }
}
output
true

Time arithmetic (LR 15):

Fortis
// accept
pure try func deadline(start: Timestamp, slack: Int<0..60>) Timestamp {
  let wait = Duration.add(Duration.minutes(5), Duration.seconds(slack)) or fail
  return Timestamp.add(start, wait) or fail
}

test "deadline is later" {
  let t = deadline(Timestamp.epoch(), 30)
  expect Timestamp.after(t, Timestamp.epoch())
}
