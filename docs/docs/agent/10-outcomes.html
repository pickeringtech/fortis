Human mode: Outcomes and failures

Outcomes and failures (LR 10)#

Agent mode. Human mode: Outcomes and failures. Source of truth: LR 10.

Preview: linear containers (LR 10.7) arrive in v0.1. The rest of this chapter (LR 10) is in v0.0.1.

Rules#

RuleStatementLR
LANG-10-01An Outcome[T] stays wrapped until consumed by an operation of LR 10.2; its success value is never reachable otherwise.LR 10.1
LANG-10-02Linear obligations survive storage in collections, fields and closures; dropping one is rejected.LR 10.7
LANG-10-03A reported failure is unreachable afterwards; annotate keeps exactly one obligation.LR 10.6
LANG-10-04noalloc try functions use the bounded failure representation on success and failure paths.LR 10.3
LANG-10-05recover without a prior report adds the recovers effect.LR 10.4
LANG-10-06Defects follow the closed taxonomy and are never catchable.LR 10.8

Facts#

  • try func f(…) T returns Outcome[T]; return v = success, fail f = failure; the call needs no prefix (LR 10.1). Patterns success(x), failure(f); by hand: Outcome.success(v), Outcome.failure(move f) for a failure binding f (LR 10.1).
  • Consuming operations, the complete list (LR 10.2):
    OperationEffectWhere
    e or failpropagatetry functions
    e or recover vdischarge, v lazy; adds recoversanywhere
    e catch n { … }block ends in recover v, return, fail or a Never callanywhere
    match e { success(x) => …, failure(f) => … }the failure arm consumes fanywhere
    report f / report f as rconsume; r: Report receiptio allowed (not pure)
    move to owned Outcome[T] / owned Failure, store in linear container or fieldtransferanywhere
    fail f (f: Failure)propagatetry functions
  • No bare or value, no ?, no call-site try, no unwrap (LR 10.2). or binds loosest: write let v = f() or fail on its own line (LR 1.1).
  • Integer arithmetic the checker cannot prove safe, as the left operand of an outcome operator, is a checked region handled like a call: total = total + r or fail, value * 10 + d or recover 0 (LR 6.4).
  • In test and property bodies or fail is implied after a fallible call nothing else consumes: expect half(4) == 2 (LR 14).
  • Failure: stable code (StringView from static), typed payload, origin, optional cause chain; linear, not copyable; created in a pure function it reads no clock and allocates no identifier; bounded payload (64 bytes inline) satisfies noalloc (LR 10.3).
  • error Name { … } with the lines code: "…", optionally payload { … } and message: "…${field}…", one per line: constructor Name(…) producing a Failure, pattern is Name(…), display template over payload fields only (not rendered in records yet, and Failure is not Displayable: read e.code and payloads, X-154, D-57; constructor calls where a Failure value is expected are refused today, D-52); library failures have no is-nameable kind: test e.code (D-58); codes unique per package and stable; payload fields trivial or length-bounded String/Bytes (LR 10.3).
  • catch: return/fail leave the function; recover v is the expression's value; give not allowed; covers only its left operand; recover after the failure was consumed (report, fail, move, match) adds nothing, otherwise it consumes and adds recovers (LR 10.4).
  • Failure match: match move f { is A(x: v) => …, is B as b => { …consume b… }, otherwise(o) => { …consume o… } }; payloads bound by copy; is without as discharges (adds recovers); otherwise(name) is required (open type); match f without move inspects only and f must still be consumed (LR 10.5).
  • report is a statement; with the log statements, the io needing no capability (diagnostic plane only); a pure function cannot report (LR 10.6, LR 11.6). A failure is recorded with report e alone, never logged as well; log.warn(…) is for what is not a failure, such as a fallback taken (LR 13). annotate(f: owned Failure, note: StringView) Failure; Failures.aggregate(list: owned List[Failure]) Failure (LR 10.6).
  • A failing try main: one report on standard error, exit status 1 (LR 4.6).
  • Linear containers: push(move x) in, pop() out as a linear T?, consumeEach(owned self, fn mut(owned T) Void) (in order, no early exit), clear() and dropping rejected, count()/isEmpty() borrow; Outcome.collect(move list) Outcome[List[T]]; a generic function holding T linearly declares T: linear (LR 10.7).
  • Defects (contract violation in trusted code, stack exhaustion, out of memory, runtime invariant): native aborts, the VM terminates the task; never a Failure, never caught, no completion value; observed only as TaskCompletion.Defect by a supervisor (LR 10.8).

Correction patterns#

E-OBL-001: dropped outcome (LR 10.1)#

Fortis
// reject: E-OBL-001
export error Missing {
  code: "store.missing"
}

pure try func lookup(key: Int) Int {
  if key > 3 {
    fail Missing()
  }
  return key
}

pure try func check(key: Int) Bool {
  lookup(key)                                  // reject: E-OBL-001
  return true
}

test "check" {
  expect check(1) or fail
}

// accept
export error Missing {

    fail Missing()
  }
  return key
}

pure try func check(key: Int) Bool {

Matching failures by kind (LR 10.5)#

Fortis
// accept
export error NotANumber {
  code: "parse.not_a_number"
  payload { position: Int }
}

export error Empty {
  code: "parse.empty"
}

pure try func firstDigit(text: StringView) Int<0..9> {
  if text.scalarCount() == 0 {
    fail Empty()
  }
  let s = text.scalarAt(0) or fail
  let d = Scalar.digitValue(s)
  if d == null {
    fail NotANumber(position: 0)
  }
  return d
}

pure try recovers func classify(text: StringView) StringView from static {
  return match firstDigit(text) {
    success(d) => "digit"
    failure(f) => match move f {
      is NotANumber(position: p) => "not a number"
      is Empty => "empty"
      otherwise(other) => fail other
    }
  }
}

test "classify" cases {
  "digit": { text: "7x", expected: "digit" }
  "letter": { text: "x7", expected: "not a number" }
  "empty": { text: "", expected: "empty" }
} as row {
  expect classify(row.text) == row.expected
}

Consuming a list of outcomes (LR 10.7)#

Fortis
// accept
export error Missing {
  code: "store.missing"
}

pure try func lookup(key: Int) Int {
  if key > 3 {
    fail Missing()
  }
  return key
}

pure try func sumAll(keys: List[Int]) Int {
  let mut outcomes: List[Outcome[Int]] = List.default()
  for k in keys {
    outcomes.push(lookup(k))
  }
  let values = Outcome.collect(move outcomes) or fail
  let mut total = 0
  for v in values {
    total = Int.saturatingAdd(total, v)
  }
  return total
}

test "sumAll" {
  expect sumAll(List.of(1, 2, 3)) == 6
  let bad = sumAll(List.of(1, 9)) catch e {
    expect e.code == "store.missing"
    recover -1
  }
  expect bad == -1
}
