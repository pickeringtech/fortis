Human mode: Effects and contracts

Effects and contracts (LR 11)#

Agent mode. Human mode: Effects and contracts. Source of truth: LR 11.

Preview: contracts (LR 11.5) arrive in v0.1. Effects, claims, noalloc and capabilities (LR 11.1, 11.2, 11.3, 11.4 and 11.6) arrive in v0.2. The observation plane and aspects (LR 11.7, 11.8) arrive in v0.5, except the diagnostic plane that report and the log statements write to (LR 11.7, LR 13), which is in v0.0.2. main's capability parameters (LR 4.6, 11.6) and the core aspect @ignorable (LR 5.5, 11.8) are in v0.0.2.

Rules#

RuleStatementLR
LANG-11-01The effect set is exactly alloc, io, mutate, nondet, suspend, block, fail, recovers; summaries are computed transitively, closed under recursion by a least fixed point.LR 11.1, 11.3
LANG-11-02Writes to fresh storage, and writes through the function's own editable parameters (its write footprint), are not mutate; writes through captures, guards or atomics are.LR 11.1, 11.3
LANG-11-03noalloc is checked against the allocation-pattern whitelist for the actual target and telemetry plan, covering failures, cleanup, closures and every async phase; a conflicting telemetry policy is rejected at the policy.LR 11.4
LANG-11-04A trusted summary is labelled trusted, never proved; trusted is rejected outside the fortis package.LR 11.3
LANG-11-05async, try and recovers are written wherever the summary has the effect; across a module boundary only written pure/noalloc count; weakening an exported function's written modifiers is a reported API change.LR 11.2, 11.3
LANG-11-06A contract contains only modifiers, forbids <effect>, requires capability A and excludes capability A; configuration never adds predicates.LR 11.5
LANG-11-07io other than report and the log statements requires an Authority parameter, except in the entry main, which receives the capabilities as parameters (or, declaring none, creates them with one direct Host.capabilities()), and in an adapter's minting function, which itself requires the capability it derives the authority from, so every authority traces back to main; Host.capabilities() anywhere else, twice, or in a main that takes a capability parameter, is rejected.LR 11.6
LANG-11-08Contracts are applied in the modifier position, before single-word modifiers, without arguments; @ applies aspects only.LR 11.5
LANG-11-09Aspects have only the parts needs, before, after, on failure, metadata; they elaborate before checking (before in application order, after reversed, on failure innermost first) and the elaborated function passes every ordinary check.LR 11.8

Summary transfer rules (LR 11.3)#

  • Call: imports the callee's summary at its actual type arguments and callback types.
  • fail is imported only when the failure leaves the function: kept by or fail and fail f; removed by or recover, catch … recover, and a consuming match, which add recovers unless the failure was reported first (LR 10.4).
  • Write footprint: per editable parameter (and editable self). At a call each footprint parameter is instantiated with the argument place: fresh in the caller → nothing; reachable from a caller editable parameter → joins the caller's footprint; otherwise (capture, Mutex guard, atomic) → mutate.
  • Fresh: a let mut initialised from a constructor, a literal or an owned call result. A binding holding a loan result is a path to the loan's owner.
  • async call: builds a future, imports only argument evaluation; await (or launch into the awaiting scope) imports the future's summary; launchParallel/launchBlocking import the work's summary minus block.
  • Callback parameter: contributes what its function type permits. A lambda literal with no pure-excluded effect has a pure type.
  • cleanup effects join every function that may drop the type.
  • report and log.info/log.warn/log.error are io but need no capability (LR 11.6, LR 13); a pure function cannot report or log.
  • Instrumentation (capture, record, completion records) does not change a summary (LR 11.7).

Contract elements (LR 11.5)#

ElementEffect on the target
pure, noalloc, …the modifier's claim
forbids recovers (any of the eight effects)that effect must be absent from the summary
requires capability Athe function takes a parameter of Authority type A
excludes capability Athe function neither takes A nor calls, transitively, a function that requires A

Contracts compose by conjunction; contradictions are rejected; pure with requires capability is a contradiction because a pure function takes no capability parameter (LR 11.5). The formatter keeps the name and prints the expansion after it: export FastCalculation pure noalloc func square (LR 11.5).

Authorities (LR 11.6)#

  • Capabilities (process-wide; created once, only for the entry main, which declares the ones it needs as parameters, func main(console: Console, files: FileSystem), LR 4.6): FileSystem, Network, Clock, Random, Environment, Process, Supervisor, Console, SecretAccess, RawSql. Other functions take them as ordinary parameters. Older code calls Host.capabilities() once in a main with no capability parameter; that stays accepted, and fortis fmt rewrites it.
  • Per-activation authorities (RequestContext, Identity, Db, Tx, TaskContext, Mail): minted by a kit's adapter from a capability, passed as a parameter.
  • Shared[A] of an authority A satisfies the rule like A; share one capability as let c = Shared.create(move out), then c.retain() per owner (no field stores a loan, LR 7.7).
  • Attenuation only narrows: fs.subtree(path).
  • Clock reads are nondet and need Clock; a pure function takes time as a plain parameter.

Aspect parts (LR 11.8)#

PartConstraint
needs name: Typetarget has exactly one parameter of Type (two: error); hooks use it with the target's mode
needs Contracttarget carries the contract
before { … }may fail on a non-try target only if an on failure of this or an outer aspect maps every failure
after(result: R) { … }read loan of the result; may fail only when R is not linear
on failure(f: Failure) R { … }owns f; must return an R or fail
metadataarguments readable by libraries through the toolchain

Arguments are compile-time constants: literals, record and variant-map literals, enum values, capture-free fn literals, declaration names. First parameter may be positional, the rest named. Specialisation: aspect a(params, ...rest) = b(fixed: v, ...rest). No around, no body access. Core aspects (LR 11.8): observe(schema) (LR 13), and ignorable(), applied as @ignorable, which lets a call statement drop the function's non-linear result without discard (LR 5.5).

Correction patterns#

E-EFF-001: pure function performing I/O (LR 11.1)#

Fortis
// reject: E-EFF-001
import fortis.host { Console }

pure func greet(console: Console) {      // reject: E-EFF-001 (a pure function takes no capability)
  console.print("hello")              // reject: E-EFF-001
}

func main(console: Console) {
  greet(console)
}
Fortis
// accept
import fortis.host { Console }

func greet(console: Console) {
  console.print("hello")
}

func main(console: Console) {
  greet(console)
}
output
hello

E-EFF-001: missing recovers (LR 11.1, LR 11.2)#

main inherits the effect from its callee and needs the modifier too.

Fortis
// reject: E-EFF-001
export error Odd {
  code: "demo.odd"
}

try func half(n: Int) Int {
  if n % 2 == 1 {
    fail Odd()
  }
  return n / 2
}

func halfOrZero(n: Int) Int => half(n) or recover 0   // reject: E-EFF-001

test "half" {
  expect halfOrZero(4) == 2
}
Fortis
// accept
export error Odd {
  code: "demo.odd"
}

try func half(n: Int) Int {
  if n % 2 == 1 {
    fail Odd()
  }
  return n / 2
}

recovers func halfOrZero(n: Int) Int => half(n) or recover 0

test "half" {
  expect halfOrZero(4) == 2
  expect halfOrZero(3) == 0
}

E-EFF-001: mutate through a capture in a pure function (LR 11.1, LR 11.3)#

Fortis
// reject: E-EFF-001
class Cell {
  export value: Int
  pure func set(editable self, value: Int) {
    self.value = value
  }
}

pure func viaClosure() Int {
  let mut cell = Cell(value: 0)
  let mut poke = fn mut[editable cell]() Void {
    cell.set(2)
  }
  poke()                              // reject: E-EFF-001
  return 0
}

test "closure" {
  expect viaClosure() == 0
}
Fortis
// accept
class Cell {
  export value: Int
  pure func set(editable self, value: Int) {
    self.value = value
  }
}

pure func direct() Int {
  let mut cell = Cell(value: 0)
  cell.set(2)
  return cell.value
}

test "direct" {
  expect direct() == 2
}

E-EFF-020: blocking inside async (LR 11.1)#

The block effect is reported in every async function that reaches it, here wait and its caller main.

Fortis
// reject: E-EFF-020
async try func wait(m: Mutex[Int]) Int {
  let g = m.lockBlocking() or fail    // reject: E-EFF-020
  return 0
}

async try func main() {
  let m = Mutex.create(1)
  let v = await wait(m) or fail       // reject: E-EFF-020
}
Fortis
// accept
async try func wait(m: Mutex[Int]) Int {
  {
    let g = await m.lock() or fail
  }
  return 0
}

async try func main() {
  let m = Mutex.create(1)
  let v = await wait(m) or fail
}

E-OBL-008: failing after on a linear result (LR 11.8)#

Fortis
// reject: E-OBL-008
export error Stop {
  code: "demo.stop"
}

export aspect strict[R]() {
  after(result: R) {
    fail Stop()                       // reject: E-OBL-008
  }
}

@strict()

  return Outcome.success(n)
}

func main() {
}
Fortis
// accept
export error Stop {
  code: "demo.stop"
}

export aspect positive() {
  after(result: Int) {
    if result < 0 {
      fail Stop()
    }
  }
}

@positive()
try func produce(n: Int) Int {
  return n
}

test "produce" {
  expect produce(3) == 3
}

Facts used when writing code#

  • Elaboration order for @a @b func f: a.before, b.before, body, b.after, a.after; a failure goes to b's on failure first, then a's; a handler that returns completes the function with its value, which is a success exit for observation (LR 11.8).
  • The hooks' effects join the summary; a hook that allocates under noalloc, reports under pure or calls Host.capabilities() is rejected by the ordinary rules (LR 11.8).
  • pure and noalloc are independent (LR 11.2). There is no nostate; no-local-mutation is an opt-in lint (LR 11.2).
  • noalloc on an async function covers construction, every poll, completion and destruction; the VM's own allocations do not count against the native claim (LR 11.4).
  • Target feature sets (core, alloc, host, async, web, browser) are not effects and not capabilities (LR 11.6).
