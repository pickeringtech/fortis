Human mode: A tour of Fortis

Overview: design invariants and notation (LR 1, LR 2)#

Agent mode. Human mode: A tour of Fortis. Source of truth: LR 1 and LR 2.

LR 1 and LR 2 state no numbered rules; they fix the invariants every later rule serves. Write code so that each of these is visible on the line.

Invariants#

InvariantConsequence when writing codeLR
Every local decision is visible: ownership operations, mutation permission, failure disposition, effect claims, observation points.Never rely on inference for these; write the marker, modifier or handler. A marker the declaration already shows is left out: an editable self call on a let mut binding, return local (LR 7.5).LR 1
Imported signatures can never be weaker than their bodies.Read the callee's signature (fortis view --symbol) instead of its body.LR 1
Library-first: program = packages, package = modules, module = one file; HTTP, data, web UI, telemetry, jobs are kits (libraries).The core imports nothing from kits.LR 1
Explicit ownership: assigning or passing an existing owned value states copy, alias or move; mutable access is editable. No hidden clones or reference counts.See ownership.LR 1
Three distinct answers: T?, Bool, Outcome[T] with ??, ||, or. Nothing is truthy.Compare explicitly (x != null, n != 0).LR 1
Linear failures: an outcome is consumed exactly once (or fail, or recover, catch, match, report); dropping one is a compile error.Every call to a try function is followed by a disposition; in a test or property body or fail is implied (LR 14).LR 1
Closed effect set: pure, noalloc, async, try are checked claims over eight effects; contracts are conjunctions of them.See effects.LR 1
Lexical loans; synchronous defer; one cancellation point (await); structured scope.End a loan early by closing a block.LR 1
Two backends, one semantics: development VM and safe-Rust native code run the same checked IR.Never depend on backend behaviour.LR 1
Absent by design: scripting semantics, runtime reflection, inheritance, macros, exceptions, implicit conversions.Do not emulate them.LR 1

Keywords that carry a decision (LR 1.1): let (new name), mut (changes), copy/alias/move/editable (how a place is used), owned/editable on a parameter, try/pure/noalloc/async/recovers and named contracts in the modifier position, or fail/or recover/catch, give, export.

Silence (LR 1.1): an unmarked argument, or the receiver of a self method, is a read loan ending when the call returns (or with the future of an async call); an unmarked for source is a read loan for the loop; an unmarked assignment is a fresh or trivial value. The unmarked receiver of an editable self method, or a fn mut being called, is the exclusive loan its root's declaration shows (let mut, editable), and return local moves the local (LR 7.5).

Removed, never write (LR 1.1): semicolons; ///, /* */; yield; or die; nostate; self: editable Self (write editable self); alias editable (write editable); alias type (a type is always nominal); within; give in a single-expression arm; fn[]; ::; operator overloading; implicit it; postfix ? for errors; new (name constructors create, of, from); return in an expression-bodied function.

Two deliberate costs (LR 1.1): (f() or fail).amount needs parentheses, so write let v = f() or fail on its own line; an async call builds a Future, and await or launch is the visible point where it runs.

Formatted source shows every inferred fact (closure kind, loan modes, a contract's modifiers), except a lambda's inferred pure/noalloc, which the function type it is passed to states (LR 1.1, LR 8.2). fortis fmt --write also rewrites older forms into the forms these pages teach where the meaning is unchanged; run it before review.

Correction patterns: notation from other languages#

All of these are E-SYN-000 (LR 3.2), a sentence outside the grammar of LR 1.1's notation.

Postfix ? for errors (LR 1.1)#

Fortis
// reject: E-SYN-000
try func parse(n: Int) Int => n

try func twice(n: Int) Int {
  let v = parse(n)?                   // reject: E-SYN-000
  return v
}

test "twice" {
  expect twice(2) == 2
}
Fortis
// accept
try func parse(n: Int) Int => n

try func twice(n: Int) Int {
  let v = parse(n) or fail
  return v
}

test "twice" {
  expect twice(2) == 2
}

Empty capture list (LR 1.1)#

Fortis
// reject: E-SYN-000
pure func countPositive(items: List[Int]) Int {
  let positive = fn[](n: Int) Bool => n > 0    // reject: E-SYN-000
  return items.countWhere(positive)
}

test "countPositive" {
  expect countPositive(List.of(1, -2, 3)) == 2
}
Fortis
// accept
pure func countPositive(items: List[Int]) Int {
  let positive = pure noalloc fn(n: Int) Bool => n > 0
  return items.countWhere(positive)
}

test "countPositive" {
  expect countPositive(List.of(1, -2, 3)) == 2
}

return in an expression body (LR 1.1)#

Fortis
// reject: E-SYN-000
pure func double(n: Int<0..100>) Int => return n * 2    // reject: E-SYN-000

test "double" {
  expect double(2) == 4
}
Fortis
// accept
pure func double(n: Int<0..100>) Int => n * 2

test "double" {
  expect double(2) == 4
}

:: paths and new (LR 1.1)#

Fortis
// reject: E-SYN-000
class Point {
  export x: Int
}

pure func origin() Point => Point::new(0)     // reject: E-SYN-000

test "origin" {
  expect origin().x == 0
}
Fortis
// accept
class Point {
  export x: Int
  export pure func of(x: Int) Point => Point(x)
}

pure func origin() Point => Point.of(0)

test "origin" {
  expect origin().x == 0
}
