# Fortis v0.0.1

Released 27 October 2026 by Pickering Technologies Ltd, under the MIT License ([LICENSE](../../LICENSE)).

v0.0.1 lets you write a real program in one package, and check, run, build, format and test it. The program can use modules and imports, statements and expressions, the core types, ownership, functions and closures, classes, enums and `match`, outcomes and failures, `defer`, and example tests. You can run it three ways: on the definitional interpreter, on the development VM, or as a native binary.

The ladder this release starts is releases.md. What it still refuses is listed in [Known limitations](../guide/known-limitations.md) (agent mode: [the same list](../agent/known-limitations.md)). The audit of every blocker is v0.0.1 readiness.

## Commands

Run these from the repository, after `cd compiler && cargo build --release`. `fortis` is `bin/fortis`.

| Command | What it does |
|---|---|
| `fortis check FILE` | Static checks. No output means the file is clean. |
| `fortis run FILE` | Run `main` on the definitional interpreter. |
| `fortisc vm FILE` | Run `main` on the development VM. |
| `fortis test FILE` | Example tests and cases tables, on the interpreter. |
| `fortisc test FILE` | The same tests, on the VM. |
| `fortis build FILE --out APP` | Native executable, lowered to safe Rust. |
| `fortis fmt --check PATH` | List files whose layout is not canonical. `--write` rewrites whitespace only. |
| `fortis view PATH` | Read Fortis source the way the compiler does. |

Each command also takes a package directory. A file under a package's `src/` is checked, run and built as a module of that package. A failing `main` exits 1, and an invalid invocation, such as a missing path, exits 2.

## Scope

Language Reference sections in this release:

- 4.1 to 4.6, one package of modules, imports, visibility and the entry point.
- 5, statements and expressions.
- 6.1, 6.2, 6.4, 6.5, 6.6 without normalisation and case mapping, 6.7 for `List`, `Map` and `Set`, 6.8, 6.9 for tuples and anonymous records, 6.11 and 6.12.

- 8, functions and closures.
- 9.1 to 9.4, classes, and 9.7 and 9.8, enums, patterns and `match`.
- 10, outcomes and failures, except 10.7.
- 12.1 and 12.2, `defer` and destruction order.

Chapters that go past this subset carry a one-line preview naming the release that brings the rest. The guide and the agent mode both carry it.

## Known limitations

Three kinds of limitation are listed, each with a workaround: valid programs the checkers reject, gaps in the library (such as missing `Map` operations), and checked programs that one backend refuses while another runs them.

- [Known limitations](../guide/known-limitations.md) for people.
- [Known limitations](../agent/known-limitations.md) for agents.

For a native refusal, the usual workaround is to run the program with `fortis run` or `fortisc vm`. `fortis build` exits non-zero in that case and writes no executable.

## How it was checked

- The merge gate passes on the release commit. It runs the syntax corpus, both static checkers, the conformance programs and packages, the acceptance programs, the pilot application's tests, the documentation examples and the plan checks.
- The three backends agree. The execution conformance suite runs each program on the interpreter, the VM and native, and compares the output and the order in which values are destroyed.
- The documentation examples run as written. Every example in the guide and the agent mode is checked by both checkers and run on the backends. 498 of 511 pass. The other 13 are recorded known failures. Two of them are listed limitations (D-52.1, D-55.8). The other eleven use features that arrive in v0.1: refinements, newtypes, generics, interfaces and `derive`.
- Every change was reviewed. Each pull request had a Codex review and a re-check, with its blocking findings fixed before merging.
- The release candidate `v0.0.1-rc.1` had a whole-release review by Codex and Grok, in four areas: the checkers, the runtime, native, and the tools and documentation. Codex's checker review could not run, so Grok's covered that area. Every blocker the review found is fixed. The readiness audit lists each blocker with its fix and fixture.

This release makes no performance claims. Performance is judged at v1.0.

## What is next

v0.0.2 is the reading release (X-345). Fortis optimises for reading, so a program marks only what the reader can't already see. In v0.0.2, the receiver of an `editable self` method is unmarked. `main` receives its capabilities as parameters. Logging is platform-native, with `log.info`, `log.warn` and `log.error`. The guide also gets a reading pass. The plan is v0.0.2-reading.md.

v0.1 is for modelling a domain: refinements (LR 6.3), newtypes (LR 6.9), generics (LR 6.10), interfaces and mixins (LR 9.5, LR 9.6), linear containers (LR 10.7), and contracts (LR 11.5).

After that, v0.2 brings effects, claims and property tests; v0.3 async and tasks; v0.4 the rest of the standard library and the core runtime; v0.5 observation and kits.
