# Known limitations of v0.0.2

<!-- covers: LR 0 -->
*Agent mode. Human mode: [Known limitations of v0.0.2](../guide/known-limitations.md). Release note: [v0.0.2](../releases/v0.0.2.md).*

Open, non-blocking defects in v0.0.2's scope, plus loud refusals (X-343): a checked program, a non-zero exit, another backend correct. Do not treat a row as a licence to change the program's meaning. A soundness bug or a wrong result is absent here unless v0.0.1 already had it: those are carried under X-416 in their own section, and code must avoid their shapes, since the checkers do not. The last section is what v0.0.2 leaves for later by design (its release note).

## Valid programs the checkers reject, and library gaps

<!-- no-citation: each row is a toolchain limitation already recorded against v0.0.2 or before; the language rules are unchanged -->

| Defect | What you meet | Workaround |
|---|---|---|
| D-51.5 | An unused import is accepted with no warning. | Delete the import. Nothing else changes. |
| D-52.1 | An error constructor is typed as its own kind, so a use that the language accepts where a failure is expected is rejected. | Match the constructor's own type, or construct the failure where its own name is expected. |
| D-52.4 | Returning a call that passes a loan-holding closure is rejected even when the result is a plain integer. | None recorded. |
| D-52.6 | A class you declare with the same name as a prelude type, such as Task, is checked as the prelude's linear type. | Name the class something the prelude does not declare. |
| D-54.6 | For a parameter named with a keyword, fortisc vm reports a generic syntax error and fortisc check reports the keyword-specific one. | Rename the parameter. Both tools refuse the program. |
| D-58.1 | Map has no iterate operation. A for loop over a map yields key and value tuples, which the language reference does not state. | Write for over the map when a key and a value together are enough. |
| D-58.7 | Map has no remove and no contains. | None recorded. Build a new map without the key, or scan it. |
| D-58.9 | Every text accessor can fail, so a comparator written as a pure function of two texts must recover. | Recover inside the comparator, or do not mark it pure. |
| D-251 | A variant whose name is also a class's is rejected by both checkers, so the program does not reach the VM. List.of(Red) with the list's element type written out runs on the interpreter, the VM and native. | Write the variant with its enum prefix, or do not declare a class of the same name. The list form already runs when the expected type is written. |
| D-252 | Both checkers reject an optional-chained method call such as lights.get(0)?.code(). The call does not reach the VM. | Match the optional and call the method on the present value. |
| D-285 | A package whose manifest the loader refuses (conformance/packages/bad.policy) makes fortis check, run and test exit 2 with a message on standard error, and fortisc check exit 1 with a names record on project.yaml. | Both tools refuse the package. Read fortisc's record; it names the manifest. |
| D-343 | A property runs 25 generated cases with fortis test and 100 with fortisc test, from different generators, so a property that fails on few inputs can pass on one and fail on the other. | Run properties with fortisc test as well, and turn a failure it finds into an example test. |
| D-344 | The executor trace of a native build has no drop event for an owned optional local, for a temporary a ?? fallback made, or for the bindings of a match arm that owns its scrutinee; the interpreter and the VM trace each, and all three trace a fallback a ?? moved into its result. Cleanup runs once on all three, and the output and the log records agree. | Compare traces on the interpreter and the VM; the native trace leaves those drops out. |
| D-363 | A tuple that holds a loan, such as (xs.get(0), 1), cannot yet be reassigned to a let mut binding that holds one, or returned from a function declared to return one: both checkers reject it as a loan where an owned value is required, although the Language Reference allows both. The same with an optional, t = xs.get(1), is accepted. | Keep the loan in a binding of its own (let t = xs.get(0)) and the other values beside it, and reassign or return those separately. |
| D-365 | A defer that changes a list, such as defer { let v = xs.pop() }, is rejected while a binding of the same block holds a loan from that list inside an optional (let t = xs.get(0)), although a deferred block runs after its block's own loans have ended. | Put the loan in an inner block that ends before the defer's block does, or make the change after the block. |
| D-400 | A function that binds a loan of a type whose cleanup does I/O (let t = alias b.t, or a ?? whose fallback fails) is charged that cleanup's effects, so a function that destroys nothing may be refused as not pure or asked to declare io. | Declare the effect, or keep such loans out of functions declared pure. |
| D-401 | A let mut cursor cannot be reassigned (the checkers report a move of a lent owner), although a cursor is owned by its binding (LR 7.7). | Make a new cursor in a binding of its own. |
| D-402 | After match move o of a binding that holds a loan (let o = xs.get(0)), the loan o held is not released, so the owner stays frozen for the rest of the block (xs.push is refused as a change under a live loan). New with this release's loan holders. | Put the match and the binding in an inner block, so the loan ends with it. |

## Defects carried from v0.0.1

<!-- no-citation: each row is a defect v0.0.1 already had, recorded for the next release under X-416 -->

The checkers accept each of these programs although the Language Reference rejects it, so a checked program can still go wrong. v0.0.1 had every one of them; v0.0.2 is no worse, and each is fixed in the release its record names. Avoid the shape, as the second column says.

| Defect | What you meet | What to do |
|---|---|---|
| D-352 | Inside a generic function, a loan can be returned or stored as if it were owned: func id[T](x: T) T { return x } and func first[T](xs: List[T]) T? { return xs.get(0) } are accepted, and the caller then holds a second reference to the argument or the list's element. | Write the function for the concrete type, where the checkers require copy or reject the loan. |
| D-355 | A loan given out of an if or match branch (give xs.get(0)), or lent by a match's scrutinee that is a temporary, such as match xs.get(0), ends with its statement, so the list can be changed while the loan is still in use. | Bind the loan with let first (let t = xs.get(0)) and branch or match on t: a let binding holds the loan to the end of its block. |
| D-356 | A field read through an optional loan with ?., such as xs.get(0)?.inner, is typed as owned, so a binding of it can change the list's own element on the interpreter and the VM. | Treat a value read with ?. through a loan as read-only: do not change it, or a binding made from it. To change a value of your own, build a new one. |
| D-357 | An owned optional binding written without a marker on the left of a ?? whose result is owned, as in let p: Token? = some ?? move d, is accepted, so p and some both own the value. | Write move some ?? move d, or copy some ?? move d. |
| D-362 | A loan held inside an optional by a let mut binding (let mut t = xs.get(0)) is treated as ended after a while or for loop whose body ends it (t = null), although a loop that runs no times, a break or a continue skips that, so the list can be changed while the loan lives. | End the loan before the loop (t = null), or keep the loan in a block that ends before the list changes. |
| D-364 | A defer that reads a binding of its block holding a loan inside an optional (let t = xs.get(0), then defer { ... t ... }) is accepted, although a deferred block may not use a binding of its block that holds a loan. | Read what the deferred block needs before it, into a value of its own (copy), and use that in the defer. |
| D-369 | A binding of a ?? whose fallback it owns, such as let t = empty.get(0) ?? move d, is typed as a loan of the list, so it can be stored in a binding of an outer block (keep = present(t)) and read there after the fallback's cleanup has run. | Keep such a binding in its own block, or move the fallback into a binding of its own first (let f = move d) and use that. |
| D-370 | On the interpreter, an unmarked copy of such a binding, or of a tuple element holding such a value (let a = t, let a = pair.0), becomes a second owner, so the fallback's cleanup runs when the copy ends, before the binding does. | Write copy t (or alias t) to say which you mean. |
| D-375 | A ?? whose fallback is the statement's own value, lent to a read parameter (show(console, empty.get(0) ?? move d)), is never destroyed on the interpreter or the VM, so its cleanup does not run; native code destroys it when the statement ends. | Bind the fallback first (let v = empty.get(0) ?? move d) and pass v, so the binding's end runs its cleanup. |
| D-376 | On the interpreter, assigning to a field of a record literal (rec.side = make(...), or a loan over a field that held a value of the record's own) does not run the old value's cleanup, and a loan assigned over such a field is cleaned up with the record while its owner still holds it. The VM runs each cleanup once, at its owner's end. | Use a class for a value whose fields are reassigned, or run the program on the VM. |
| D-379 | A fn once closure may return a loan from a move capture (fn once[move t]() Token from t { return move t }), which the consuming call destroys: both checkers accept it, the interpreter and the VM keep the value until the receiving binding ends or read it destroyed, and native code refuses the build. | Return the captured value itself from a closure returning the owned type, or let the caller keep the binding and lend it to the closure instead of moving it in. |
| D-388 | A tuple built around a value of the function's own (let t = (empty.get(0) ?? move d, 1)), bound first and returned inside present as a from result, passes both checkers; the interpreter destroys the value at the call and the caller then reads it destroyed, and the VM never runs its cleanup. | Return the owned value from a function returning the owned type, or keep the fallback in a binding of its own (let f = move d) that outlives the result. |
| D-389 | Inside a returned match arm, an if giving a loan on one branch and the function's own value on the other (let v = if flag { give x } else { give move d }; give v) passes both checkers, and both running backends destroy the moved value at the call, so later reads see it destroyed. | Give every branch a loan, or return the owned value from a function returning the owned type. |
| D-392 | A loan taken from a temporary receiver, such as let t = fresh().get(0) (also .first(), ?? make(...), or a cursor of a temporary), passes both checkers; the temporary is destroyed at the statement's end and t then reads the destroyed element on the interpreter and the VM; native refuses the build. | Bind the temporary first (let xs = fresh()) and take the loan from the binding. |
| D-393 | A pure function may print through a dropped value's cleanup: the io of a cleanup is not attributed to the function that drops the value, so both checkers accept it and every backend prints. | Do not drop a value whose cleanup does I/O inside a function declared pure; give the value to the caller. |
| D-394 | A lent match payload (match xs.get(0) { present(x) => ... }) is destroyed at the arm's end on the interpreter, and on the VM for a plain optional, rather than at its owner's end, so a read of the element after the match sees it destroyed; native is right. | Read what you need inside the arm, or bind the loan first (let t = xs.get(0)) and match on t. |
| D-395 | A result declared from one parameter (from xs) that lends another (ys) is rejected for a direct return but not through give, a match expression or an expression body, so the loan is recorded against the wrong owner and ys can change while the result lives. | Declare the result from the parameter it lends, and return it directly. |
| D-413 | On the VM, an owned value recovered by a catch expression whose result the statement discards (discard (g() catch e { report e; recover make(...) })) is never destroyed, so its cleanup does not run; the interpreter and native code run it. The or recover form, and a catch whose value a let binds, run it on the VM too. | Bind the catch's value (let x = g() catch e { ... }), so the binding's end runs the cleanup, or write or recover. |
| D-414 | An expect outside a test body, in an ordinary function or in a deferred block, is accepted by both checkers, and a failing one has no defined outcome: the interpreter stops with a Python traceback and writes no record, the VM reports a dynamic check failure, and native code does not build the program. | Write expect in test bodies only. In a function, test the condition with if, and fail or return. |

## What v0.0.2 leaves for later

<!-- no-citation: each row is a limit of this release that its release note lists; the Defect cell names the record of a gap left open on purpose, and is empty for a limit by design -->

| Defect | What you meet | What to do |
|---|---|---|
|  | The older forms are accepted alongside the new ones, so a reader may meet both until the code is migrated. | Run fortis fmt --write on the code. It rewrites each older form where the program means the same. |
| D-404 | fortis fmt never rewrites Int.shiftLeft(a, b) or fail to a << b or fail, although the two are the same operation; Int.add, sub, mul, div and rem are rewritten. | Write the operator form by hand, or leave the named call. The two mean the same. |
|  | fortis fmt does not rewrite a logging call, add @ignorable or derive Default, or rewrite a main that reads its Capabilities record other than field by field (a capability inside an interpolation, or the record moved whole). | Make those changes by hand. Each is the author's choice. |
| D-406 | fortis fmt keeps a pure or noalloc written on a lambda, although the function type the lambda is passed to already states it; it prints no inferred one. | Remove the modifier by hand if you want the shorter form. It changes nothing the checker decides. |
|  | Checked operators cover Int only. The sized integer types (Int32, UInt8 and the rest) have no checked, wrapping or saturating operations yet; they are planned for v0.4. | Give the operands a refined type, or test them first, so that the operation is proved. Or compute in Int. |
|  | fortis fmt prints a module's inferred facts back only when the module checks on its own, so a module of a package that needs the rest of its package to check is not given them. | Nothing changes in what the program means; the checker infers the facts either way. Write a fact by hand where you want it shown. |
